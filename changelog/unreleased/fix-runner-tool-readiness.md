## Agent: a model for each cloud row, and why an agent cannot start

- The Agent page's Who does the work table has an Editing and suggestions row under Cloud models, between Daily analysis and Chat panel: rewriting selected text, New task's draft, keyword and competitor suggestions, Knowledge › Add, analysis rule proposals, New playbook's draft and the other helpers a person asks for on a page.
- Each cloud model row picks its own model, as models are good at different things. Editing and suggestions › Settings opens a dialog of its own, titled Editing and suggestions, with Same as daily analysis (the model named) and the enabled chat models; until it has a model of its own, its row says Same as daily analysis and it runs on the daily analysis's model. Daily analysis › Settings is titled Daily analysis and changes only the default chat model, which the chat panel and Editing and suggestions follow unless they have a model of their own. An own model that can no longer answer marks the row as needing attention, and the helpers fail instead of quietly using another model.
- The page and Model services descriptions, quick setup step 1 and the glossary name editing and suggestions too, and Daily analysis reads "Finds opportunities daily and reviews project knowledge weekly".
- Model services without an enabled chat model now say so and link to Model services, instead of saying no model service is connected.
- The error for an article image that does not belong to the task points to Add image in the article's toolbar, no longer to the removed Edit directly.
- The agent status says why an agent that is not online cannot start, from what the runtimes report now: no runtime, only other people's personal runtimes, none online, or on an online runtime the agent's coding tool needs sign-in, is out of quota, lacks the agent's model, is not installed, is turned off or is still being detected. The computer is named for administrators and its owner. The chat panel's task_get passes the reason with the tool's sign-in command.
