## Timers: one slow firing no longer stops the others

- NocoReach's timers share one schedule executor that runs one firing at a time, and each source awaits its whole read inside its firing: GitHub trends' first read of a project slept about 6.5 seconds between some 70 searches, and Google sync, GitHub backfill, competitor research or AI questions can take minutes to hours. Meanwhile the task, sync and every other timer stood still, and shutdown waited for the firing to end. A firing still running after 60 seconds, or when the server shuts down, is now left to finish on its own: nothing is cancelled, so each source keeps its retries, spending and status; the other timers run again, the slow timer's next firings are skipped until it ends, and the log says which timer overran and when it finished. Shutdown waits at most 15 seconds more for such work.
- GitHub trends no longer waits between searches for a demo or simulated project, which is answered in process: a demo's first read of two projects took about 15 minutes of pauses and now takes moments. Each GitHub request keeps its 20-second deadline, and a request that gets no answer is reported with the run's other errors.
