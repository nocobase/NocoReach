## Search performance and Traffic: open without waiting for Google

- Search performance builds its query and page tables from the data already synced when it holds every day of both periods and at most 100,000 query and page pairs in each, so those tables no longer ask Search Console. A filter, a country, a recent project, a range longer than three months or a site with more pairs still reads Search Console, and Country / region, Device and Search appearance read it the first time a date range is shown.
- A report past its lifetime answers at once from its saved copy while a new one is read in the background, and the page replaces it by itself, saying meanwhile when the report shown was saved. A copy older than seven days is not shown; the page waits for the new report instead. API keys and scripts always get a new report, as before. A new day's date range answers the same way from the previous day's, except Country / region, Device, Search appearance and a row's detail, which load on their own. If a new one cannot be read, a line under the date range (and in Sitemaps, a row's detail and a keyword's site days) says when the report shown was saved and why, such as an authorization that has expired.
- Reports over days older than the sync reads again are kept for 90 days instead of six hours, so opening a row or a breakdown of the same days again does not ask Google. A fixed range ending within the last seven final days is read again at most once a day, in case Google published them late.
- Exports, hand-offs and a row's detail use the period the tables hold, and the online agent's tables always cover the period it states.
- The scheduled sync readies the default range's tables and breakdowns too, so they are there before anyone opens the page, for projects someone has opened in the last three days or just connected. Other projects have only Traffic's default view read every six days, so it still opens at once; their daily sync and the read of their preliminary days go on. A report Google refuses in part is read ahead at most every six hours, though a person opening it still retries sooner.
- Until the day's sync lands, Search performance's tables end at the last synced day instead of asking Search Console, and the ⓘ names the period they cover. A day the sync found empty counts as not published yet when it would be the tables' last day.
- Traffic's report is read once a day, when the day's sync moves its date range, instead of every six hours, so the preliminary days at the end of its line can lag by up to a day.
