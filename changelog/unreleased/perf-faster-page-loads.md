## Page loads: the shell is built once, page code downloads early, and restarts keep the Google data snapshots

- A full page load built the shell again, and sent all of its requests again (projects, membership, invitations, notifications, the interface language), two or three times: the authorization plugin refreshes permissions when the realtime connection opens and when its permission topics become ready, and the shell was keyed on that refresh. The shell and the workspace cache are now rebuilt only when permissions may have changed: a permission-changed event, a connection that is ready again after it dropped, or a permission snapshot that differs from the one before. Permission checks still follow every refresh.
- A page's code starts downloading when the application opens at its address and when its route mounts, beside the session, membership and access checks. It still renders only once access is granted, and a page the user may not open says so even when its code failed to load.
- The snapshots built from every synced Google day are kept in `nrSnapshots` (`sync-snapshots:<project>`, up to 4 MiB) with what they were built from, so a restart or a deployment restores them instead of rebuilding them while every request waits. A copy built from other stored data is never used, a build inside a transaction is never kept, and demo cleanup removes the copies with their projects.
