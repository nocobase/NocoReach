## Chat panel: answers questions about all of a project's tasks

- In a project's conversation, `task_list` lists that project's tasks unless the model names another project or asks for every project (`allProjects`). A page holds up to 50 tasks instead of 10, and a larger `limit` reads 50 instead of failing; a page that would pass the tool output limit holds fewer and gives `nextOffset`. `status` `open` or `closed` narrows to unfinished or finished tasks.
- Each listed task names its number, state, playbook, owner, the pages it changes (the ones its task page shows, at most 5 with a count of the rest) and the opportunity and place it came from, so a question such as "are any of the change tasks duplicates?" is answered from one or two calls. Listing no longer looks up Runner readiness for every task; only `scope: executable` does, and `task_get` keeps the full detail. The answer also lists the projects it read, by id and name, and `project_data` names the project's id.
- A tool call whose arguments break the tool's schema now tells the model which field broke which rule ("projectId: must be the numeric project id, such as "1" …"), for every chat tool; any other tool failure still says only that it was rejected. Project and task ids sent as numbers are accepted.
- A reply that uses all 16 of its tool steps no longer fails with "This turn reached the tool step limit": the model answers once more without tools from what it has read, says what it could not check, and the answer ends with a quiet line saying it covers only part of the data (side panel and Insights).
