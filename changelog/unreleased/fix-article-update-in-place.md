## Articles: an existing article's other languages get the primary's changes in place

- Updating an existing article in several languages no longer translates the whole new primary into the other languages. Once the primary is approved, each language the article already has is edited from its own text with the same changes (phase `update`): the run gets what the primary changed, the title and description before and after and the body as edits block by block, each with the unchanged block before it, and keeps the other paragraphs and their existing wording. If only the title or description changed, only those fields change. A language the article does not have yet, every language of a new article and Translate into other languages are still translated in full, now always from every field of the approved text.
- A run that writes the other languages and returns none of them is refused by `task result` in words (`articles.draft.othersMissing`), so the Agent submits what it wrote. 2026-10-28 (T-53): a failed script left the earlier run's English-only file to be submitted, and the approved English passed as the translation with Chinese and Japanese unchanged.
- The task page names the update: Approve and update other languages, the step Update other languages, "The Agent is updating Chinese, Japanese with the changes made to English", and a review titled after it that opens on the first edited language as its changes. A version that changed none of the other languages no longer reads "The translations are ready": it says which languages have no changes and offers Update again (or Translate again), Request changes and Publish English only; one with some unchanged says which. The reading page has the same actions. The start dialog's language help says how an existing article's languages are written.
