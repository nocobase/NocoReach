## Insights and the menu: fewer repeated reads while pages load

- Each time the realtime connection opens and each of its two permission topics becomes ready, the route checks access to Insights again and unmounts the page meanwhile, as before. When the page comes back from such a re-check within 10 seconds, in the same session and permissions, it now takes the state, the current situation and the waiting tasks it had already read, or the reads still in flight, instead of sending them again, and does not ask a second time for the unjudged changes to be judged. The day's conversations, the analysis status and the playbook list are still read again. The page stays hidden while access is checked; a permission change, a connection ready again after a drop, a failed permission read or another account reads everything again. Opening Insights again, even within those 10 seconds, reads it afresh as before.
- A state read that started before Ignore, Hand off to agent or a newer read of the state, and answers after it, is no longer shown: it could put an opportunity just ignored back on the list.
- Every move between pages, every window focus and every minute read both the Opportunities and Tasks counts (`nrStrategy/badges`) and the connected sources that decide which data pages the menu lists (`nrHealth/connected`), and a move aborted the reads still in flight while the server went on with them. A page load followed by five moves and a focus within 15 s sent 14 reads; it now sends 2. The sources are read on load, every minute, on focus once a minute has passed, and after a change; never on a move between pages. The counts are read on load, every minute and after a change; a move or a focus reads them only when no read is in flight and the last one is more than 15 s old, and keeps the counts on screen meanwhile.
- A change made here (a connection, a decision, a task update) reads the menu again at once even while an older read is in flight, and that older answer is never shown. Saving, tracking, following or removing keywords now updates the menu at once too, without reading the counts. Another tab, another user, the CLI or the API still shows within about a minute, as before.
- Opening Insights asks the model to judge the changes the latest analysis left without a verdict. Visits at the same time (several tabs, a reload, the call after an analysis) now share one model call instead of each making its own. A change the model was asked about and still left without a verdict is not asked about again from Insights for 30 minutes; it is judged by the next analysis, after those 30 minutes, or at once when another change joins it or a new analysis replaces it. The call after each analysis is never held.
- When judging fails, the call that failed still answers with the cause and status as before; the visits after it answer with that status and the minutes until it is tried again: 2 minutes when the provider could not be reached or turned the call away at once, 30 minutes when trying again soon would not help (no default chat model, a call the model rejected or that may have been billed). Changing the default chat model or its service's connection lets the next visit try at once. Each real failure is logged once. Insights reads the analysis again only when something was judged.
