## Pages: long ranges with page-level history

- Pages showed the same figures for the last 90 days, 12 months and all time: page-level data (Search Console query × page, GA4 pages) was only kept from the day a project connected. A background job now fills it back up to 16 months for both sources, a week at a time, after the daily sync has run, so the longer ranges and their changes show real figures. It shows in the Google connection's sync jobs as "Page history".
- Pages' visits and search figures are summed by the database from the page × day table the page drawer reads, instead of reading every synced day. On 252's data (84 days, about 24,000 addresses) a range takes 0.2–0.5 s on SQLite instead of 0.3–1.6 s, and a longer history no longer makes every range change parse its JSON (about 1.3 MB a day).
- The table keeps each row as numbers, with addresses and sources in tables of their own: 84 days of 252's data take 26 MB on Postgres with the indexes and addresses instead of 44 MB.
- After the upgrade the table is summed again in the background from the data already stored; until that finishes (about 11 s on 252) the first Pages read of a range is slower than before (3–4.5 s on 252's data on SQLite).
- The query and page samples behind Traffic's page queries and the analysis cover at most the last 180 days, so a long synced history is not held in memory and page history writing older days does not rebuild them.
- The snapshots behind Traffic and the analysis are built a week of page data at a time instead of from every day's rows at once: on 252's 210 days the build held about 600 MB of memory at its peak and left the server at 1.1 GB.
- Page history no longer holds back Traffic's background reads while it runs, a failed page history job is tried again a day later, and page days removed after a fill are filled again. Sync now and Retry failed jobs stay available while page history runs, and it can be paused.
- When Pages' figures cannot be read, Website content says its sample covers only the last 180 days of a 6, 12 or 16-month range; Traffic's page queries name exactly the days they sum.
- A GA4 page history week the daily sync had already stored no longer fails the job; page history skips resources no longer selected and waits while Google refuses the authorization. The data behind Traffic and the analysis is no longer rebuilt every night when nothing new was synced.
