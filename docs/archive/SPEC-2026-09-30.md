## 当前产品方向 2026年9月30日

NocoReach 定位为官网与博客运营者的 AI 内容优化工作台：看数据与建议 → 确认优化工作 → Agent 修改内容仓库 → 预览确认发布 → 观察效果。产品保持简单，主要入口为概览、优化工作、内容，连接与 Agent 配置进入设置。内容为轻量索引，正文由仓库维护；当前不做完整 CMS 或独立项目管理。

在现有 NocoBase 3、Portal 与连接插件基础上修改。复用数据分析、机会讨论、执行记录和版本能力，重做固定六阶段任务体验，支持持久化看板拖动；任务完成与效果观察分开。简单修改无需逐步方案表单，复杂内容按需设置审核点。推送分支及 PR、预览和确切版本发布确认构成首个仓库执行链路。

## 1. 产品定位

NocoReach 是面向市场人员的 Agent 驱动的数据洞察与内容行动工作区。用户先看到数据洞察，再通过自然语言探索机会与行动，系统结合自身表现和目标市场变化，持续发现值得投入的内容机会，主动提出方案；经人确认后执行内容创作，在多个节点接受审核和调整，最终经确认发布，并观察后续表现。

核心问题：“结合我们的目标、自身数据和市场变化，现在值得做什么内容，为什么？请把值得做的事情推进到可以发布，并持续观察结果。”

Agent 从数据洞察开始贯穿整个流程，在机会讨论中帮助明确具体行动目标。数据接入、分析页面、机会、任务和内容成果共同支撑这条流程，AI 不再是完成数据工具之后追加的一轮功能。

主要行动聚焦内容产出与现有内容优化。完整广告投放、销售执行、通用多 Agent 管理平台不由本版自动扩展进来。

## 2. 已确认的产品主线

接入数据与维护项目背景 → AI 主动呈现数据反馈、洞察与初步建议 → 用户选择机会或自由探索 → 围绕机会讨论，明确该行动的目标、受众与做法 → 确认进入任务 → 确认执行方案 → 按工作类型产出与多轮审核 → 实际执行或发布 → 验证结果。

首页在用户开始对话之前就提供可阅读的机会，不以统一目标表单或空聊天框作为开始条件。洞察可以服务不同目标；用户不必先确定唯一项目目标。数据不足时呈现待核查信号及限制，不硬凑建议。

## 3. 项目背景与行动目标

长期项目背景包括产品、官网、主要市场、受众和可用数据，可持续维护，作为分析背景而非固定筛选门槛。旧版已确认目标保留为历史偏好，不删除，不强迫所有机会服从它。

具体目标在某个机会的讨论中逐渐明确，例如改善某类搜索点击或帮助开发者上手。不同机会可以产生不同目标与行动；确认任务时携带本次行动目标、交付要求、机会和证据，不需要先修改项目统一目标。

用户既可围绕首页机会讨论，也可自由提出问题。讨论必须带上选中机会的观察、证据、建议及限制，返回页面可继续原讨论；切换机会不得悄悄覆盖用户正在编辑的行动。

## 4. 数据范围与洞察依据

产品面向广泛的数据接入，逐步结合以下来源。范围纳入产品方向不等于连接器已经存在，也不要求全部来源齐备后才开始产生价值。

| 数据类别 | 作用 | 边界 |
| --- | --- | --- |
| 官网与内容资产 | 理解产品表达、已有主题、内容缺口和更新情况 | 内容采集不能代替访问与搜索数据 |
| GA4 等网站分析 | 观察访问、来源、参与和已配置的转化事件 | 未接订单或 CRM 时不解释为成交或营收 |
| GSC 等自有 SEO 数据 | 观察查询、页面、点击、曝光与搜索变化 | 自有搜索表现不是全市场需求 |
| 开源相关数据 | 理解项目关注、社区反馈与需求信号 | 具体平台与指标待细化；不将关注度等同购买需求，不与网站流量混算 |
| 行业与目标市场数据 | 引入 Google Trends 等趋势来源、关键词研究工具筛选出的行业关键词及相关需求证据 | 来源、接入方式、地域、时间口径和费用逐项评审；不能冒称已接入 |

AI 应把自身数据变化与行业变化联系起来，结合目标和已有内容判断能做什么。输出区分事实、假设、建议与缺失信息，注明来源、时间、数据覆盖和限制。不同来源允许相互补充，不能强行合成无依据的统一分数。

## 5. 持续观察与主动方案

主要使用方式是：接好数据后，系统持续观察，主动把洞察与初步行动建议呈现给用户；用户也可以主动发起分析、追问或补充要求。

持续观察需要持久运行与可追溯记录，不等同于用户打开页面时计算一次。运行周期、部署保障和提醒渠道在实现时明确；当前本地运行不能承诺关机后仍持续工作。

观察频率与提案频率分开。数据不足、暂未发现可行动机会时应如实说明，不为了定期输出而生成任务。提案需要考虑既有方案、进行中的行动及用户反馈，避免重复建议。

方案至少让用户理解：为什么值得做、服务哪个目标与受众、准备产出或优化什么、主要依据是什么、有哪些不确定性。可以建议关键词文章、更新现有内容等，具体类型逐步扩充。

待审核方案不等于已授权执行。批准方案后进入创作；暂缓、拒绝和修改应保留反馈，具体规则在开发时细化。

## 6. 多轮人机内容协作

确认选题或方案不足以直接进入发布。内容创作必须支持多个有意义的人工确认点，以及每个节点内的讨论、修改和再次审核。

审核应尽早暴露方向、材料和结构的问题，减少全文完成后返工。用户可以通过自然语言反馈，也可以直接编辑；AI 后续修改应尊重已确认内容和人工修改，并保留可追溯版本。方向变化时允许回到较早阶段。

四类机会共用任务流程，AI 按具体交付物提出执行步骤和审核点，人确认后推进。复杂文章可分提纲和初稿，简单修改无需固定全文流程。每个步骤都明确由 AI 还是人完成，资料缺口与外部操作明确交接。详见 [任务执行设计](TASK-EXECUTION.md)。

业务工作与单次 AI 执行应分别追踪：生成成功不代表审核通过，审核通过不代表已经发布，已发布不代表达成增长目标。失败时保留已有成果，避免丢失人工编辑或重新执行整个流程。

## 7. 发布与效果反馈

发布必须基于用户确认的最终内容版本、目的地和授权范围。确认方案或某一中间稿不自动授权发布；最终版本发生实质变化后不能沿用旧的发布确认。

发布渠道与集成顺序尚未确定。尚无连接器时可以交付发布材料并由用户记录实际发布信息，但必须区分准备完成、待发布和已发布，不把导出当作发布成功。

复盘关联目标、方案、实际发布内容、执行时间和基线。数据不足时继续等待或明确结论受限，不虚构效果，不把相关性当因果。复盘结果应可供下一次洞察使用。

## 9. 沿用的数据、权限与体验底线

- 日期对比使用等长周期。原有 7 天至 16 个月的目标范围不等于实际已覆盖；历史不足时明确限制。
- PV、日均 UV、事件、查询与页面口径清晰；跨天 UV 不累加冒充周期独立访客。明细截断要说明，不以明细合计替代全站总量。
- 无数据、缺失、不完整和真实零值区分；同步成功时间与数据可用截至日期分别展示。
- 连接需说明配置、授权、同步、可用、延迟、失效、失败与暂停状态，支持日志、恢复和断开影响说明；断开不默认删除历史。
- 同步沿用持久任务、幂等分区与原子更新；更换资源不混入旧站数据。官网采集需确定域名、范围、频率和失败行为。
- 付费研究先显示条件和费用估计并取得明确授权；预算、缓存、防重复继续有效。估计不等于供应商强制上限；unknown 保留并核对，不自动重新收费。
- 项目身份、权限、数据范围和凭据隔离由后端验证；Agent 不越过用户权限。现有单项目管理员路径不是多租户验收。
- 第三方内容仅作证据，不作为执行指令；秘密不进入提示词、浏览器或日志。外发、发布与其他外部写入受对应授权限制。
- AI 调用失败需诚实提示，保留编辑内容与确定性能力；任务重试不得自动重复外部写入。
- 保留加载、空态、无匹配、权限不足、失败和成功反馈；复用缓存不跳过鉴权，保存失败不丢内容，未保存离开有提醒。

## 10. 文档与开发约定

本版取代“先页面、再接入、最后 AI”的三轮产品组织方式，历史实现与验收记录继续有效。后续按端到端工作切片推进，每个切片同时考虑 Agent、数据、人工参与和失败恢复。

开发前先盘点可复用实现，明确本次调整和新增范围，再补充必要的交互、数据模型与验收细节；不能把本版所有目标视为一次性开发授权。具体未决事项包括首批开源与趋势连接器、观察频率、内容审核节点、提醒方式、发布渠道、模型选择及界面布局。

设计、实现、发布、验收四个状态独立记录。细节可在开发中迭代；改变已确认产品方向或替换可用模块时应说明原因和影响，避免无依据重建。

## 11. 发现机会首页（最新确认）

沿用 /home，以机会卡片作为页面主体，替代独立的网站流量、自然搜索、开源占位指标卡及统一目标表单。保留详细分析入口与旧路由兼容。

每条机会包含：发生了什么、为何值得关注、可追查的数据依据和时间范围、不确定性，以及初步行动建议。数据和建议呈现在同一条机会中。未接入来源不编造结论，缺少证据的内容标为待核查信号。

用户打开首页先看到已保存的 AI 洞察；首次尚无结果时展示分析状态和失败恢复，不能用规则模板冒充 AI 结果。更新洞察保留之前结果直到新结果成功，记录生成时间与数据截止时间。本轮按首次打开和用户更新生成，后台持续观察另行交付。

点击讨论某条机会后进入独立的、带上下文的讨论子页面，逐步形成可编辑行动及该行动目标。确认后直接进入现有任务列表；确认行动不授权创作结果发布。允许自由探索，不要求先选机会或确认项目目标。

桌面利用可用宽度，机会卡片优先；对话与编辑在子页面呈现，窄屏顺序排布。数据覆盖和连接状态放入辅助说明及证据入口，不再占据三个与洞察分离的主卡片。

## 2026-09-28 — 机会库

新增机会库 /opportunities，侧栏和发现机会首页均有入口。所有成功保存的生成批次持久保留，更新机会只改变首页最新批次。每条保留 ID、生成时间、当时证据及独立会话入口；历史机会可继续讨论及确认行动，确认使用原始证据。机会库支持搜索、来源与任务关联筛选及分页，不默认删除或合并相似机会。当前版本发布时已有批次兼容纳入；此前已覆盖且未留存的内容不虚构恢复。

机会库使用紧凑列表，按行展示机会标题及建议摘要、来源、生成时间与数据截至、任务关联及讨论入口。详细证据在机会子页查看，保留搜索筛选和分页；窄屏按行内分组显示。

## 数据接入与首次使用

数据接入按“连接平台、提供资料、自定义连接”组织，AI 协助识别来源、推荐、配置解释和验证；用户确认授权、资源与范围。首次使用从产品背景与来源选择走到有依据的首批机会，不要求接齐全部来源或预先确认统一目标。完整设计及能力边界见 [数据接入与首次使用设计](DATA-ONBOARDING.md)。首批统一现有 Google 接入并新增公开官网／文档与 GitHub；文件及自定义接口等按实际交付开放。公开单页、GitHub 首批接入与连接助手已实现；完整新用户初始化及多项目能力仍待完成，具体交付边界见专题文档。

## 联合复用与执行演进（2026-09-30，目标设计）

在线 AI 员工承担资料齐备的分析、方案与文本产出，本地 Agent 承担需要文件、浏览器、仓库及 CLI 的工作；通过统一业务契约回传成果，执行位置不决定权限。任务、步骤、Run、成果版本、审核、发布与效果状态分别追踪。真人负责人不由 Agent 替代，运行成功不自动批准、发布或完成任务。

真人负责人需要明确认领；在线文本执行在后台留下独立记录。AI 生成、人工修改分别保留成果版本，批准或打回指向具体版本。打回后需新版本再审，迟到结果不能覆盖人工修改；审核通过仍进入待实际执行，不能自动标为发布或目标完成。实现和验收状态见 [M1 记录](../m1/README.md)。
