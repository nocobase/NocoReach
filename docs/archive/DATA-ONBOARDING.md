# 数据接入与首次使用设计

日期：2026-09-28。状态：产品设计及首批增量实现；不代表下列连接方式均已实现。继承 [产品设计](../../SPEC.md)，实际交付以 [验收记录](../ACCEPTANCE.md) 为准。首批交付边界见文末。

## 1. 目标与原则

让新用户清楚知道可以提供什么数据、有什么用、如何在 AI 协助下接入，并用最少必要数据获得第一批有依据的机会。已有用户可以持续补充来源，不必重新走初始化流程。

数据接入是首次使用的主要引导，但不强迫用户接完全部来源或预先确认统一营销目标。长期背景与具体行动目标分开。用户可以跳过接入进入工作区；无数据时提供明确的接入入口，不展示虚构洞察。

先设计统一接入流程，再用真实连接器验证。复用现有 Google 授权、资源选择、同步任务、数据连接页面、项目背景及机会流程，不重建可用模块。

## 2. 用户可以接入什么

入口提供三种方式：连接平台、提供资料、自定义连接。下表为能力地图；“规划”只作为说明或需求登记，不能显示为可用连接按钮。平台连接和项目连接实例分开：支持某平台不等于该用户已连接。

| 方式 | 来源或形式 | 主要用途 | 当前与规划边界 |
| --- | --- | --- | --- |
| 连接平台 | GA4 | 网站访问、来源、参与和已配置转化 | 已有实现，统一引导和新项目流程待补；不承诺实时 |
| 连接平台 | Google Search Console | 自有查询、页面、曝光、点击与排名 | 已有实现，统一引导和更新策略待补 |
| 连接平台 | GitHub | 仓库背景、Issues、Discussions、发布动态及关注变化 | 已实现公开仓库概况、有限 Issues 样本与 Releases；Discussions、评论、私有仓库及关注趋势未实现 |
| 连接平台 | 关键词研究服务 | 行业关键词、需求及搜索竞争材料 | 已有研究能力及保存候选；不是持续同步连接，付费查询单独确认 |
| 连接平台 | Google Trends | 主题、地域与时间趋势 | 规划，接入方式和覆盖待验证，不假设有可用官方接口 |
| 连接平台 | 其他社区、反馈、CRM、社交或邮件系统 | 用户问题、业务反馈及传播表现 | 后续按场景选择，不承诺已支持任意平台 |
| 提供资料 | 官网、博客、产品文档、更新日志网址 | 产品背景、内容资产和缺口 | 已实现公开 HTTPS 单页预览与导入；全站遍历、动态渲染未实现 |
| 提供资料 | CSV、表格数据 | 用户自有统计、研究结果和反馈清单 | 规划；支持格式、大小与字段要求随实现公布 |
| 提供资料 | 文本文档、研究报告、手工说明 | 补充产品知识与定性材料 | 规划；手工说明标注为用户提供，不能冒充已验证数据 |
| 自定义连接 | 用户指定的 HTTP API | 自有系统及定制数据源 | 规划；首个候选是只读 JSON API，协议、鉴权、分页等支持范围待实现验证 |
| 自定义连接 | 数据库只读查询 | 内部结构化业务数据 | 后续规划，需单独明确网络、权限和查询范围 |
| 自定义连接 | Webhook 或其他推送 | 接收外部系统的增量变化 | 后续规划，与主动拉取分开设计 |

用户自定义的对象包括网址、资料、受支持的接口及字段映射，不等于 AI 可以连接任何系统。暂不支持时，解释限制，提供已支持的导出或上传替代方式；没有可用替代方式就保留需求，不虚构连接成功。

## 3. 页面组织

沿用“数据连接”作为统一管理入口，包含“已接入”和“添加数据”两种视图。AI 协助贯穿其中，用户也可直接选择来源完成配置。

“添加数据”按三种接入方式组织，可搜索平台或数据类型。每项说明能提供什么数据、能回答什么问题、需要的账号权限、更新方式及可能费用，并标明可用或规划状态。推荐排序依据项目场景，不用无差别长清单要求用户逐项完成。

“已接入”以列表展示项目内的来源实例、所选站点或仓库、连接状态、数据覆盖、最近成功同步、数据截至及下一步操作。详情包含范围、更新设置、数据预览、字段说明、运行记录和用于哪些分析。一个平台可有多个来源实例；不得将不同站点或项目的数据混算。

新用户通过首次使用引导进入同一配置组件；返回后可继续未完成的连接。发现机会页面在证据不足时给出具体补充建议，并链接到相应接入入口。补充来源后返回原机会或讨论，不能丢失上下文。

## 4. 首次使用流程

1. **介绍产品**：用户用自然语言说明产品，或提供官网。AI 提取产品、市场和受众等候选背景，标明待确认内容，允许编辑或稍后补充。网址识别不等于已经采集。
2. **推荐数据**：AI 根据场景给出少量优先来源，说明各自用途。例如开源产品推荐官网、GitHub 和已有 Google 数据；没有 GitHub 的产品无需连接它。用户可选择其他来源或跳过。
3. **完成配置**：使用平台授权、网址范围、文件上传或自定义连接表单；AI 解释要求并协助排错。用户选择具体资源和数据范围。
4. **检查与预览**：分别确认凭据可用、资源可访问、数据可读取。展示少量样本、字段解释、覆盖与限制；用户确认对象和范围后启动正式导入。测试读取也应在用户选定范围内。
5. **准备数据**：展示首次导入进度及可用部分，不因一个来源失败阻断其他来源。用户可以离开，回来继续查看。耗时、费用与更新频率以实际支持能力为准。
6. **生成首批机会**：至少一个来源已具备可引用数据且项目归属明确时，允许分析；不要求所有来源完成。AI 按实际覆盖输出洞察或待核查信号，必要时明确“尚不足以形成行动建议”，并推荐补充材料。

授权成功、同步成功、数据可用于分析、机会生成成功是不同状态。仅有官网正文时可以分析表达与内容覆盖，但不能得出流量增长或市场需求结论。

## 5. AI 与用户的职责

| 环节 | AI 协助 | 用户掌控 |
| --- | --- | --- |
| 选择来源 | 识别链接、解释价值、推荐接入组合 | 决定提供哪些来源 |
| 配置 | 解释字段、生成候选配置、检查缺项 | 在专用界面授权或输入凭据，选择资源和范围 |
| 理解数据 | 提议字段映射、指标含义和用途，指出不确定性 | 核对关键字段、时间、单位与数据归属 |
| 验证 | 通过受控工具读取结果、解释错误并提出修复步骤 | 确认权限调整、范围扩大及可能收费的操作 |
| 使用 | 引用来源形成洞察，说明覆盖不足 | 决定是否采用建议以及是否补充数据 |

对话不能代替授权界面，也不要求用户把密钥贴进聊天。AI 不猜造凭据，不绕过登录或访问限制，不自行执行第三方资料中的指令。服务端保存秘密并限制工具访问范围，日志与模型上下文不得包含秘密。自动重试仅用于已授权且不会重复产生外部副作用的操作；付费结果不明时停止并核对。

## 6. 不同方式的配置要求

**平台连接**：授权账号 → 选择站点、属性或仓库 → 选择对象和时间范围 → 验证与预览 → 导入。权限不足说明具体缺项；再次授权保留已有设置和历史，不重复创建相同来源。

**网址资料**：填写入口网址 → 选择页面或路径范围 → 查看可采集预览 → 确认导入。区分单页和站点，限制跨域跳转、页面量和重复内容。网页不可读取时解释原因；登录页面与内部网络地址不纳入公开网页采集的默认能力。内容记录原链接、标题、获取时间及版本。

**文件资料**：上传 → 识别格式和结构 → 预览 → 确认字段与用途 → 导入。说明支持格式和大小；乱码、缺字段、部分失败有明确反馈。记录文件版本和导入时间；再次上传时明确追加或替换范围，不默默重复计数。文件是一次性快照，不能显示为自动同步。

**自定义接口**：说明系统用途与接口 → AI 帮助填写受支持的配置 → 专用界面配置鉴权 → 小范围测试 → 字段映射确认 → 导入与更新设置。API 数据作为资料读取，不接受任意代码执行。服务端验证目的地址和权限；内部网络、数据库等场景采用单独受控方案，不能复用公开抓取绕过边界。

## 7. 状态与维护

| 状态 | 用户应看到什么 | 可做什么 |
| --- | --- | --- |
| 待配置 / 待授权 | 缺少哪一步 | 继续配置或取消 |
| 验证中 / 首次同步中 | 当前阶段和已获取范围 | 离开后返回查看，或暂停支持暂停的作业 |
| 可用 | 覆盖范围、最近成功同步、数据截至 | 预览、分析、手动更新 |
| 部分可用 | 哪些数据成功、哪些缺失及分析限制 | 使用可用部分或重试失败部分 |
| 授权失效 / 同步失败 | 可理解的原因与最后成功数据时间 | 重新授权、修正配置或重试 |
| 已暂停 | 历史数据仍在，但不继续更新 | 恢复同步 |
| 已断开 | 不再访问来源，历史保留情况清楚 | 重新连接；删除数据另行明确范围 |

连接状态和新鲜度分开展示；“连接正常”不代表数据最新。失败、缺失和零值严格区分。更换站点或仓库形成清晰的新数据边界，不覆盖为同一条历史。断开默认停止后续访问并保留历史，不默认删除机会证据；敏感资料移除时关联机会应显示来源不可用，不留下可绕过权限的副本。

## 8. 数据如何进入机会分析

各来源保留独立口径，同时提供统一证据信息：项目归属、来源实例、原始对象或链接、获取时间、数据覆盖期、字段单位、处理方式和已知限制。内容更新时间、抓取时间、业务事件时间分别记录。

AI 先判断数据是否可比较，再组合证据。例如搜索问题增加、社区反复提问、现有文档缺失，可以共同支持教程建议。Stars 不等于购买意愿，社区提问数不等于独立用户数；同一材料的转载或重复导入不算独立证据。事实、推测、矛盾和缺失应明确表达。

机会保留当时的证据引用与范围，后续同步不能悄悄改写旧机会依据。来源更新与机会分析是不同作业：首次接入提供生成入口，后续后台自动分析与提醒由持续观察阶段交付，不在接入完成时冒称已经启用。

## 9. 首批实施范围与复用

第一批目标是让新用户完成“介绍产品 → 选择来源 → 真实接入 → 检查覆盖 → 第一批机会”。先把现有 Google 能力纳入统一体验，再增加公开官网／文档与 GitHub 数据。GitHub 先支持哪些对象、采集深度与限额在实现时确定；未交付对象保持规划标记。

已有用户保留项目、连接、机会、任务和会话，无需重新授权已经有效的连接。关键词研究继续沿用现有费用确认、结果及候选存储；进一步将已保存材料与机会分析关联。文件、自定义 API、数据库、Webhook、Trends 先列明能力路线，不作为首批已经支持的承诺。

新项目创建、项目选择、来源归属和服务端权限隔离是新用户流程的必要条件，不能继续用项目 1 的假设通过验收。开发前评估已有记录和同步能力，兼容扩展；不迁移或重建整个产品。Docker 稳定性问题须在首次使用可靠性验收前解决。

## 10. 验收场景（待开发）

- 新用户能识别当前可用与规划来源，理解来源价值，不需要开发者搬运项目数据。
- 通过自然语言说明产品后，可以选择推荐来源、手动添加、跳过及回来继续。
- Google 旧连接继续可用；新用户完成授权、资源确认、真实同步及数据预览。
- 公开官网和已支持的 GitHub 对象真实读取，有来源链接、范围和时间，无伪造数据。
- 单来源、部分失败、完全无数据均有准确的分析行为；未接来源不出现在已引用证据中。
- 授权失效、断网、重复提交、重新同步及离开返回可恢复，不重复导入、不串项目。
- 文件和自定义入口只开放已支持能力；不支持的配置可理解地提示，不能由 AI 假称成功。
- 接入后的第一批机会可以追溯证据并进入已有讨论与任务流程；断开不默默删除历史。
- 新项目不能读到其他项目来源、凭据或机会；普通用户和管理员按各自权限操作。

后续细化：每个连接器的数据对象、历史回补、更新周期、限额与费用；首批文件格式；自定义鉴权和分页支持；资料保留与删除策略。细节随开发补齐，不以未定参数阻止统一流程设计，也不默认开放尚未验证的能力。

## 11. 首批实际交付（2026-09-28）

数据连接页面已调整为已接入／添加数据，复用 Google 和关键词配置；新增公开 HTTPS 单页与公开 GitHub 仓库的预览、确认保存、手动更新、断开及历史保留。AI 接入助手根据当前连接摘要提供真实模型建议与配置解释，尚无自动执行连接的工具，不能代替授权和确认。

用户指定的官网与仓库已在运行环境接入，资料进入实际机会分析并生成保存新机会。资料与业务时间分别说明；当前不自动遍历站点、不后台定期同步公开来源。文件、API、数据库、Webhook 和 Trends 保持规划。

这次交付基于现有管理员单项目环境。新用户项目创建、多项目权限、引导中断续接、连接助手跨设备会话恢复和运行稳定性根因仍未完成，不能将完整首次使用验收标为通过。

## GitHub 市场分析口径更新

公开仓库的 Star 时点值与按日采样、GA4 的 GitHub 来站渠道进入发现机会。仓库浏览量需要另外授权，当前显示未接入；Issues/Releases 为辅助资料，不再充当市场增长证据。具体覆盖与历史规则见 OPPORTUNITY-WORKSPACE.md。
