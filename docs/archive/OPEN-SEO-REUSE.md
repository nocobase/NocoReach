# OpenSEO 产品研究与页面复用方案

记录日期：2026-09-30。状态：已纳入产品设计，尚未开发。NocoSolution 与 NocoProject 研究已完成，实施顺序以 [联合复用开发计划](INTEGRATED-DEVELOPMENT-PLAN.md) 为准：先准备任务执行与共用 UI，再将研究页面接入机会到任务主线。本文件保留 OpenSEO 专项复用细节，表中批次表示其模块内部优先级。

## 1. 研究依据与定位

研究对象：[every-app/open-seo](https://github.com/every-app/open-seo)，源码基准为 [0ffff93101043aad7600a3b6a499a0cd2887ef49](https://github.com/every-app/open-seo/tree/0ffff93101043aad7600a3b6a499a0cd2887ef49)。此前研究检查了源码、官网及许可证，未运行其登录后页面，未验证付费接口或完整业务流程。页面存在与源码结构可复用不等于运行质量已经验收。

OpenSEO 将关键词研究、域名分析、排名跟踪、网站审计及 AI 可见性等研究能力组织成 SEO 工作台，并通过 MCP、Skills、项目背景和报告供 Agent 使用。市场研究依赖 DataForSEO 等外部服务；开源页面不意味着数据免费。

NocoReach 继续以“多来源证据 → 发现机会 → 讨论行动目标 → 确认任务 → 内容协作与审核 → 执行及验证”为主线。引入 OpenSEO 的研究页面与交互，为这条主线补充可核查的市场证据；沿用现有首页、机会库、任务与 NocoBase 3 技术基础。

## 2. 页面复用候选

| 页面 | 值得复用的内容 | NocoReach 落点及依赖 | 候选顺序 |
| --- | --- | --- | --- |
| 关键词研究 | 研究标签页、结果表格、意图和难度标签、筛选排序、批量选择、移动端结果 | 升级现有关键词研究；沿用连接、查询、费用预览和研究记录 | 第一批核心 |
| 已保存关键词 | 标签分类、筛选、批量操作、导出 | 扩充现有外部研究候选；保留与关键词选题的关系，后续接机会讨论 | 第一批核心 |
| SERP 详情 | 排名、标题、域名、链接、分页和加载反馈 | 作为关键词详情中的搜索结果区域；额外采集仍需费用确认 | 第一批核心 |
| 项目背景 Context | 产品定位、写作偏好、竞品、重点页面、研究记录 | 扩充项目设置，让用户检查和修正 Agent 背景；具体字段待合并研究后确定 | 第一批可选 |
| 域名分析 | 域名及路径范围、关键词／页面视图、筛选和历史 | 候选竞品研究入口；需新增对应数据接口与费用策略 | 第二批候选 |
| 排名跟踪 | 趋势、关键词 × 日期历史矩阵、检查状态 | 重点关键词观察及发布后验证；需历史存储、采集和调度支持 | 第二批候选 |
| 网站审计 | 问题、页面、性能及问题详情视图 | 与完整站点采集共同评估，将问题接入优化任务；现有单页采集不足以支撑 | 后续评估 |
| AI 可见性、外链 | 品牌提及与引用、模型回答对比、外链和引用域名 | 新增来源能力，需独立明确业务场景、覆盖和费用 | 暂缓 |

已有自然搜索、网站分析和连接页面优先保留；是否抽取其局部交互，在后续统一设计中判断，不新增重复入口。研究页不直接替换发现机会首页。

## 3. 建议的首个开发切片

候选流程：关键词研究结果页 → 关键词／SERP 详情 → 已保存候选管理。

- **复用现有能力**：DataForSEO 连接、查询预览、预算检查、缓存、幂等请求、研究记录、候选保存与关键词选题入口。
- **调整现有页面**：结果表格、过滤排序、选择反馈、详情展示、加载／空态／失败态和窄屏布局；沿用现有路由与产品视觉规范。
- **新增候选能力**：标签、批量保存与导出等操作。存储字段、去重及批量失败行为在正式开发前细化，不能仅复制按钮。
- **主线衔接**：候选可携带原研究依据进入机会讨论，经人明确行动目标并确认后进入任务。具体关联方式待统一设计；保存候选不等于认定机会或自动创建任务。
- **已有欠项**：真实关键词研究结果到候选、选题的完整业务验收尚未通过；页面改版不能将该欠项自动标为完成。

项目背景作为独立可选增量：产品描述、定位、写作偏好、竞品和重点页面可供 Agent 使用并由用户修正。OpenSEO 的 `current_goal` 不直接成为我们的统一目标门槛；长期背景与每项行动的独立目标继续分开。Agent 写回规则、来源与修改记录在实施前细化。

## 4. 代码移植与数据边界

两边均使用 React 19、Tailwind 4、TanStack Query/Table、Recharts 和 Lucide，展示组件有复用基础。整页仍需适配以下差异：

| 层面 | OpenSEO | NocoReach 处理 |
| --- | --- | --- |
| 路由和页面入口 | TanStack Router/Start | 接入现有 React Router 与 NocoBase Portal，不另起应用 |
| 样式 | daisyUI 及其主题类 | 映射到现有组件、颜色和工作区样式，避免全局样式冲突 |
| 数据和认证 | 自有 Server Functions、数据库、项目上下文和认证 | 通过现有连接插件和后端权限适配，禁止复制前端后绕过鉴权 |
| 计费和外部请求 | 自有研究查询、计费及缓存机制 | 沿用费用预览、明确授权、预算、缓存和幂等策略；unknown 不自动重试 |

移植前按实际文件检查依赖及版本；不整体引入其认证、计费、遥测或部署体系。保留现有研究记录、候选和用户编辑，数据结构优先兼容扩展。当前单项目管理员试运行限制不因引入组件而消失。

普通结果筛选、排序、已加载数据分页和查看历史不产生新查询费用。OpenSEO 的 SERP 翻页可能触发购买更深结果；在 NocoReach 中必须明确区分“浏览已有结果”和“付费获取更多”，后者先预览并确认，不因翻页、刷新或重试自动收费。

研究结果保留供应商、地区、语言、研究方式、采集时间及范围；市场搜索量和流量估算不冒充本站实际数据。缺失值不作零值，排名跟踪与 GSC 平均排名口径分开。AI 引用保留证据与限制，不将候选收藏视为收益判断。

## 5. 许可与源码定位

该基准版本使用 [MIT 许可证](https://github.com/every-app/open-seo/blob/0ffff93101043aad7600a3b6a499a0cd2887ef49/LICENSE)，允许复制、修改与商业使用，复制或实质复用时须保留版权和许可声明。实际移植时记录来源版本、文件及修改范围，并更新仓库 `THIRD_PARTY_NOTICES.md`；第三方依赖与素材另行核对。本次仅记录设计，没有引入第三方代码。

OpenSEO 源码定位（以下均相对其仓库根目录，使用上述固定版本）：

- `src/client/features/keywords/`：关键词研究、结果表格、SERP 组件及状态逻辑。
- `src/client/features/saved-keywords/`：候选列表、标签与批量操作。
- `src/client/features/projects/project-context/`：项目背景、竞品及重点页面。
- `src/client/features/domain/`、`rank-tracking/`、`audit/`、`ai-search/`：后续研究候选模块，均位于 `src/client/features/` 下。
- `src/serverFunctions/keywords.ts`：现有组件的数据契约参考，不直接替换 NocoReach 后端。

NocoReach 实施入口：`apps/portal/src/pages/keyword-research.tsx`、`keyword-api.ts`、`seo-opportunities.tsx`、现有 strategy 模块及 `plugins/connections/server/`。开始开发时重新核对最新实现与工作区改动。

## 6. 待统一设计与未来验收

NocoSolution 与 NocoProject 研究已完成。联合计划明确了任务主线、在线与本地执行分工、统一 UI 以及关键词切片的前置依赖；具体字段和适配契约在 M0 确定，不预设未经验证的工作量或发布日期。

选定范围后至少验证：

- [ ] 原连接、研究记录、候选与旧入口继续可用，人工编辑和来源证据不丢失。
- [ ] 查询结果、详情、保存候选真实跑通；如选定机会衔接，验证原证据进入讨论与任务。
- [ ] 筛选排序与已有结果分页不付费；新增采集显示费用并确认，失败和 unknown 不重复收费。
- [ ] 标签及批量操作如纳入范围，覆盖去重、部分失败与刷新恢复；导出范围和数据口径清楚。
- [ ] 加载、空态、失败恢复、桌面与窄屏、现有视觉一致性通过实际页面检查。
- [ ] 接口校验项目和用户权限；缓存不越权，不能以当前单项目路径冒称多租户验收。
- [ ] 实际移植代码具有完整来源及许可记录。
