# API 密钥

在“设置 → API 密钥”中管理脚本和集成凭据。该入口与「成员与角色」等设置并列；页面需要成员页面访问权，服务端还会独立检查成员资格、密钥归属及操作权限。

## 创建与使用

1. 选择“个人密钥”。具备密钥管理权限的人也可选择“组织密钥”。
2. 点击“创建密钥”，填写名称、有效天数和范围。默认有效期 90 天，可选 1–365 天。
3. 选择全部项目或指定项目，以及读取、读取和写入或业务管理。后面的级别包含前面的级别；只能选择当前可授予的范围。指定项目的密钥不能操作应用级设置。组织密钥还需选择服务身份持有的业务角色。
4. 创建成功后立即复制秘密，并通过团队认可的秘密存储方式保存。关闭后无法再次读取秘密；列表、记录和截图都不包含完整秘密。
5. 请求时将秘密放入 `x-api-key` 请求头。实际权限始终是身份当前权限与密钥范围的交集，业务负责人、审核和数据边界仍然生效。

个人密钥属于本人；移除成员、禁用账号或收回角色会限制后续请求。普通成员不能通过修改请求中的人员编号读取或操作别人的密钥。组织密钥归应用，由现任有权管理员管理，不随创建者离职失效；其服务身份不会出现在成员和任务负责人列表中。

## 轮换、停用与记录

- 在密钥行菜单选择“轮换”，确认后旧秘密立即失效，没有并行宽限期。轮换保持原范围，按原有效天数重新计算到期时间。立即更新所有使用它的集成。
- “停用”永久删除凭据，使用旧秘密的请求会认证失败。组织密钥停用时还会禁用服务身份并清理其业务角色分配；过期凭据已被清理时，也可以执行停用以完成服务身份清理。需要新的权限或项目范围时创建替代密钥，再停用旧密钥。
- 点击名称或“操作记录”可查看安全的创建、轮换和停用记录。停用或过期凭据被框架清理后，历史记录仍可查看。
- 已过期、停用或被清理的密钥不能轮换。失效凭据可能返回认证失败或不存在；有效凭据越权通常返回权限拒绝，隐藏对象存在性时沿用业务的不存在响应。

无权访问时请联系管理员；登录失效时重新登录。网络或服务暂时失败可重试，权限拒绝和对象不存在不提供重复重试入口。

生产旧密钥换发、维护窗口及整体备份恢复仍须按照[切换说明](ACCESS-CUTOVER.md)在上线前确认。页面交付不代表已完成生产切换。
