# Navigation count contract

`nrStrategy/badges` returns `{ insights: number, opportunities: number, tasks: number }`. The existing action wrapper checks NocoReach membership and project existence. No new permission mechanism, migration, or persisted count is introduced.

- Insights counts the changes still to act on (`insightPending`): `todaySuggestions(state, 50)` plus current signals not cited by those rows whose shared `signalDisposition` is pending opportunity or standalone `do`. Keep the existing v2/v3 selection and display bound. A cited opportunity counts once even with multiple signals. This excludes the personal task strip.
- Opportunities counts deduplicated `rowsFor(state)` with `opportunityState === pending`: latest analysis, raised within `opportunityKeepDays` (14) analysis days of the latest one, restored history, or confirmed manual `resultOpportunities`, excluding ignored and handed-off cards. Manual cards retain their pending state through analysis rotation. `change === new` is not a filter. Results itself has no badge.
- Tasks counts raw project task records using the home waiting strip's owner fallback and state: current user's todo/review, excluding archived/cancelled; ownerless records count for administrators. The task list and badge share `TaskService.tasks`, with complete 200-record pagination rather than silent 2000/5000-record caps.

Pure predicates and snapshot types live in `shared/strategy-pending.ts`, `shared/strategy-model.ts`, and `shared/task-pending.ts`. The existing client modules re-export their previous public names.

`NavBadgeProvider` is mounted beneath the session-keyed `MeProvider` and `WorkspaceCacheProvider`. It creates a fresh context per project. `useNavBadge('insights' | 'opportunities' | 'tasks')` returns `{ count: number | null, status: 'loading' | 'ready' | 'error', label: string }`. Only `ready` has an accurate count. A ready zero can hide the badge; loading/error must not be presented as zero. Invalid, missing, negative, or fractional counts fail closed. Project isolation comes from the request context and keyed provider; the response does not echo a project ID.

The provider refreshes on navigation, focus, every minute, and `refreshNavBadges()`. A refresh keeps ready counts on screen until its response arrives, so switching menus does not blink the badges; a failed refresh still clears them. Opportunity decisions, signal decisions/verdicts, analysis completion, handoffs, and task updates publish refresh events. Draft task creation publishes its event only after identifying the created task; both keyword and section handoffs share that boundary. Insights reloads strategy state and its task collection together after a signal handoff so the same page reflects the new task. Project/session changes clear state; unmounted or superseded requests cannot publish results. PM-311 menu route mapping, orange badge rendering, collapsed/mobile layout, and accessibility presentation are included in this delivery as described below.

## Menu presentation

The application adapter `usePendingNavigationBadges` maps `/opportunities` and `/actions` to the template menu's route-name-keyed `badges` input. Insights (`/home`) keeps this branch's no-badge behavior; the `insights` count stays in the response. This preserves PR #59's intent while its product scope awaits owner confirmation. Only ready, positive counts render one `SidebarMenuBadge` per menu entry. The shared application presentation layer uses the existing `attention` and `attention-foreground` tokens for a solid orange background and dark digits. The beta.68 template owns the rounded badge, row placement and label space, displays `99+` above 99, and includes the exact count in the link's accessible name and tooltip. Numeric text is hidden from assistive technology. In desktop icon mode the primitive hides the visible number and the template shows a corner dot; the mobile sheet uses the same entries.
