## 审查发现及复验

进行了一次独立设计审查及一次独立验收审查。主代理完成复验，没有用第二轮审查替代实际验证。

- B1：成员 ID 原先限制首字符数字，与原生 UUID 不符。改为接受原生不透明 ID 并查验用户存在；字母及零开头 ID 测试、原生真实用户分配、浏览器成员登录均通过。
- G1：新错误边界硬编码中文。新增双语键并使用应用翻译函数，翻译覆盖检查及构建通过；未主动让 React 崩溃来截图该 fallback。
- D1：证据表陈旧、重启/权限/深色窄屏/已填充交互不足。补做项目切换、生产重启、成员角色、负责人切换、机会交接、页面合成数据、深色/宽松/窄屏和通知，并在此逐项记载。外部数据页面全部有数据交互仍未认证，保留为验收缺口，不能将本项视为无条件全通过。
- 额外原生适配修复：SQLite 排序字段迁移；领域异常转原生状态码；通知 idempotencyKey；用户服务事务连接及锁外成员校验，消除任务负责人更新死锁。原生测试和浏览器相关动作均复验。
- 生产环境缺少 public origin 时框架拒绝 Cookie 写请求。设置真实 `APP_PUBLIC_ORIGIN` 后正常，文档记录要求，没有放宽安全检查。
- 基线保留项：原有布局、组件及交互沿用；不按新脚手架风格重做可用模块。部分旧注释措辞不影响行为，未借迁移扩大整理范围。

## 2026-10-09 补充核对：是否遗漏迁移

线上已经替换为新应用，本轮没有把当前线上当作旧版进行比较。比较依据为仓库保留的 `apps/portal`、`plugins/connections`，以及替换前保存的首页空状态截图。结论是**本轮未发现明确漏迁的业务功能或新增回归**，不是全部功能端到端验收完成。

### 源码覆盖

- 旧业务路由中的 47 个显式路径、27 个页面动态加载入口，在新路由中均有对应项。这是静态集合核对，不等于逐个 URL 浏览器实测。
- 旧 pages 目录 103 个文件、新目录 107 个文件；旧版缺少同名目标文件的仅登录、注册及两处找回密码页面，由新框架认证入口承担。两组业务组件 reach、seo 各 11 个文件均无缺项。
- AST 盘点得到新旧各 216 个具名资源动作，缺失和新增集合均为空。此计数限于可静态识别的注册动作，不代表 216 个动作均已执行。
- 原入口引用的业务模块均在新 runtime 中引用；旧 tables 建表逻辑由原生迁移替代，执行模块改为新目录构建产物。16 项周期任务及独立每日分析调度有对应挂载。
- 文件存在与接口注册只能排查结构性遗漏；外部凭据、模型响应、长期调度和真实仓库行为仍需运行证据。
