# 在界面配置采集器

已部署好 NocoReach Collector 后，可以直接在 **数据接入 → 小红书 / Bilibili / YouTube** 填写连接，无须修改配置文件或重启 NocoReach。

1. 使用 NocoReach 管理员账号打开对应平台。
2. 在“采集器连接”填写服务地址，例如 `https://reach-collector.nfvd.net`，以及该服务配置的访问令牌。若当前使用部署配置，先点击“填写地址”。
3. 点击“保存”。随后填写搜索词或视频链接，按平台面板上的操作开始采集。

默认采集器环境已经就绪，页面无需设置浏览器、登录状态或本地路径。保存连接只保存配置，不会发起平台请求，也不代表已成功采集。实际采集失败时，面板会显示具体原因，已有结果保留。

模拟环境使用网络配置管理的模拟采集器，连接卡片只读，无须填写真实服务地址或令牌。已有的项目连接配置不会覆盖模拟采集器；切回真实环境后，原连接配置仍然保留。

## 地址和令牌

- 填写服务的根地址或反向代理的基础路径，不追加 `/health`、`/search` 或 `/video`。该地址需要从 NocoReach 服务端访问。
- 远程服务使用 HTTPS；同机服务可使用 `http://127.0.0.1:端口`。地址不包含用户名、密码、查询参数或片段。
- 令牌与 Collector 保持一致，为 32–256 个可见 ASCII 字符，不含空格。只在页面的令牌输入框填写。
- 令牌加密保存，不会再次显示。编辑时留空保留原令牌；修改地址时必须重新填写，避免把原服务的令牌发送到另一个地址。

三个平台可以使用同一地址和令牌，分别在各自入口保存即可；Collector 需已启用相应平台能力。连接按项目和平台分别生效，不会自动修改其他项目或平台。

## 已有配置与修改

现有 `config.yml` 的 `nocoreach.browserCollectors` 仍然有效。保存界面配置后，当前项目的当前平台使用新连接；配置失败不会退回其他采集器。尚未设置界面连接的项目继续使用原部署配置。此版本支持继续编辑界面连接，暂不提供删除界面连接、切回部署配置的按钮。

采集或保存正在进行时，请等待结束后再修改。若其他管理员已修改配置，点击“重新加载”会清除当前输入并读取最新配置，然后重新编辑。

若提示采集或配置保存正在进行，当前输入会保留，等待结束后再次保存即可。若登录会话已变化，页面会刷新登录状态；确认当前账号后重新填写并保存。

更换采集器或令牌会保留已保存的笔记、视频及采集条件，并清除旧连接的成功验证状态。YouTube 原有的每日读取设置保持不变。

普通成员可以查看采集结果，只有管理员可以查看和修改连接设置。服务端缺少加密密钥时不能保存令牌，需要部署管理员处理。

## 已保存凭据无法读取

部署管理员应先恢复保存凭据时使用的 `secrets.keys`，保留原密钥版本，并重启应用重新加载配置。恢复期间不会自动使用其他采集器；小红书和 Bilibili 已保存的笔记、视频仍可查看。

如果原密钥已无法恢复，需要重新配置连接：先停止应用并备份数据库，再由部署管理员删除 `nrVariables` 中名称精确匹配 `NOREACH_COLLECTOR_<平台>_<项目 ID>` 的那条失效配置，随后重启应用并重新填写完整地址和令牌。平台值为 `xiaohongshu`、`bilibili` 或 `youtube`。不要删除平台内容数据。删除项目连接后，该平台会恢复使用部署配置（若有），应在恢复采集前确认连接已重新保存。

平台说明：[小红书](XIAOHONGSHU-COLLECTOR.md)、[Bilibili](BILIBILI-COLLECTOR.md)、[YouTube](YOUTUBE.md)。
