# 设计决策

以下按 2026-09-28 已确认结果整理，不伪造更早的确认日期。

| 决策 | 原因与约束 |
| --- | --- |
| 页面内 AI 优先，不以全屏聊天作为核心入口 | 用户需要基于当前数据直接决策；不能只是外部 AI 的聊天替代品 |
| 导航按用户任务，而不是数据供应商 | 自有搜索、外部关键词研究职责分开，连接统一管理 |
| 迁移需求不进入产品 | 旧备份/旧实例与历史快照是本次初始化手段，不是市场用户核心功能 |
| 网站与产品兼容未来开源表现 | 网站与开源有独立数据口径；接入后再启用对应子页 |
| 合并搜索概览与自有搜索表现 | 减少重复入口，将趋势与关键词证据集中展示 |
| 一级标题无图标、子菜单不同图标、全部展开 | 提高可发现性，避免折叠隐藏功能 |
| 行动计划为一级分组 | 任务列表保留；行动草案与效果复盘明确禁用占位，未交付不假装可操作 |
| 付费请求不自动重试 | 网络异常不等于未计费；unknown 保留并对账 |
| 先补齐第二轮，再做真正 AI | AI 不能掩盖数据覆盖、接入和权限缺失 |
| GitHub 维护当前设计与交付事实 | SPEC 不堆叠互相冲突的历史结论；历史理由交由决策记录和 Git 追溯 |

后续变更需补充：提出原因、确认结果、影响页面/数据/API、验收变化。尚未确认的建议不写成既定规格。
