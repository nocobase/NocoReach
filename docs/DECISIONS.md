# 设计决策

## 2026-10-09 — 将现有功能迁至 nocobase/nocobase3 新应用

用户确认使用官方 `pnpm create @nocobase/app@latest` 创建 `apps/nocoreach`，以独立 SQLite 数据库开发和验证。目标是 `nocobase/nocobase3` 的应用框架，不是原 `@nocobase/server@3.0.0-alpha.7` 宿主。复用当前已实现的页面、交互及业务规则，按照新框架实现应用路由、身份、持久化和所需服务端能力；不迁移旧数据库，不兼容 alpha.7 运行环境，不修复原版已有问题，不补齐原版未实现功能。验收区分迁移引入的问题与既有问题，并用浏览器验证功能、比较当前部署的界面。

| 决定 | 原因 |

| 决定 | 原因 |

## 2026-10-04 — 数据说明用 ⓘ，不用黄色文字

| 决定 | 原因 |
| --- | --- |
| 解释数据、指标、概念的文字放进 ⓘ（鼠标移上去或点开），放在它解释的东西旁边：整页说明在标题旁，某一列在表头，某张图在图标题 | 用户：严谨的产品不会在页面下面堆黄色说明字，而是用带圆圈的 i 小标，点或移上去弹出解释 |
| 指标和概念的说明写在一张词表里（`pages/glossary.ts`），表头和指标卡按名字自动带上 | 同一个词全产品同一句解释，新页面不用另写 |
| 出错和要你处理的事照常显示（红色提示框），不藏进 ⓘ | 藏起来会被忽略 |

## 2026-10-04 — 界面统一：AI 标志、折叠框、确认框

| 决定 | 原因 |
| --- | --- |
| AI 说话或干活的地方只用 NocoProject 的 Agent 头像（紫色圆角方块 + 机器人）；AI 生成或建议的内容旁边放小紫星；本机 Agent 用显示器图标、在线 AI 用闪电图标区分 | 用户发现绿色圆形、紫色方块、电脑图标混用，风格不一致；按 NocoSolution 前端规范 §S4.1、§S5.1，`--agent` 紫色只表示 Agent |

| 删除、断开、放弃修改前，用页面内的确认框（标题点名对象、一句后果、按钮写动作，危险操作红色），不用浏览器的 confirm | 规范 §9.3；浏览器弹框样式和产品不一致 |
| 所有状态胶囊（接入状态、验证、任务状态、难度）都用同一个 Tag | 规范 §5.3；原来有灰色胶囊、手写小标签几种样子 |

## 2026-10-04 — 剩下的数据源怎么接

| 决定 | 原因 |
| --- | --- |
| Google Trends 走已接入的 DataForSEO，每周自动查一次 | 官方 Trends API 还在内测、要申请；DataForSEO 每次约 $0.011，一周两个请求，花费可以忽略 |
| X 用项目自己的 Bearer Token，设每月上限（默认 $5），到上限前停止；不请求作者 | X 2026 年起只按条付费（约 $0.005/条）；Google 搜 x.com 收录太少；作者会按用户另外收费 |
| Discord、Slack 都做，团队自建机器人／内部应用，粘贴 token 先检查再保存 | 有些项目的社区在聊天群；Slack 只有内部应用不受 15 条/分钟的限制；Discord 机器人能看到的人数超过 1 万要向 Discord 申请 |
| 竞品动态只用免费数据：官网 sitemap 新页面、GitHub 新版本和 Star；关键词留在“查域名” | 每周自动看不该花钱；关键词按次收费，由人决定什么时候查 |
| CMS 先不做 | 页面内容已经由网站内容读到；写入 CMS 在后续方向 |

## 2026-10-04 — 记忆：建项目后自动写初版，之后的更新先给建议

用户提出记忆应能随使用更新，并在一开始根据官网和资料自动生成。确认：建项目后在后台自动生成初版（只填空分区，已写的变成建议）；之后每周看任务修改意见、新资料、官网变化和审核通过的成果，给出建议，点“补充”才写进记忆——记忆每个任务都读，写错会影响所有任务，所以不自动写入。新资料的建议沿用添加弹窗里的确认。检查失败不自动重试。

## 2026-10-03 — 第 4 项：不接仓库的分析、撤回、初步数据

| 决定 | 原因 |
| --- | --- |
| 做法里没有“Agent 修改”时，Agent 分析不需要仓库：在空的临时目录里只根据任务资料和公开网页分析；有修改步骤的做法（含技术修复的“出方案”）仍要先接仓库 | 调研、关键词调研、大纲这类任务不需要源码；方案步骤是为修改服务的，没仓库时写不出具体改法 |
| 本机 Agent 的只读步骤允许搜索和读取公开网页（WebSearch、WebFetch） | SPEC 写明分析要读公开网页；无人值守运行时这两个工具原本会被当作“需要授权”而拒绝，没接仓库时更需要 |
| 撤回用 GitHub 自带的回退（GraphQL revertPullRequest，同 PR 页的 Revert 按钮）开回退 PR，由你在 GitHub 合并；只对经 NocoReach 合并的 PR 提供 | 各种合并方式都能正确回退，不改写历史；合并前你还能再看一遍 |
| 初步数据单独存放，只画在图上、写在卡片下，不进合计、对比、信号、每日分析和效果观察 | 最近一两天 Google 还在补数据，混进去会误报“下降”或算错效果 |
| 共享资料先出方案：建议随任务带数据摘要、每日分析带最近任务、接受的分析文档进知识库；MCP 查询与在线 AI 读仓库先不做 | 用户要求先看方案；先用最简单的办法补上两个缺口 |

## 2026-10-02 — OpenSEO 第 2 批：关键词研究与关键词；付费查询不再逐次显示费用；页面铺满宽度

| 决定 | 原因 |
| --- | --- |
| DataForSEO 查询点了就查，页面上不显示每次的价钱；花费在数据接入看（本月已花、累计、预算、结果不确定次数）；月度预算仍是硬上限，超了就停并提示去数据接入调整 | 用户改定：每查一次都显示费用很奇怪。取代“先显示费用、确认后才查”。保险留在预算上限、30 天复用、结果不确定不重试，付费请求仍只在用户点击时发出 |

## 2026-10-07 — 英文界面

- 用户要求先做英文。
- AI 内容的语言（用户选）：每个项目设一个语言，建项目时选，默认跟创建人的界面语言；不按每个人的界面语言分别生成，免得费用成倍。
- 名词译法和顺序（用户确认）：先做界面英文，部署给用户看，再做 AI 内容和英文文档。

**做法**：沿用 NocoBase Portal 自带的语言设置（头像菜单切换、存进账号、切换后整页重新加载）。NocoReach 自己的文字用中文原文作键、英文放 `en.json`：中文界面零改动，漏翻时退回中文，不会显示空白或键名。

**服务端不改**：前端会解析服务端中文句子里的数字（例如“是平时的 3 倍”生成“↑ 3 倍”标签）；如果服务端直接返回英文，这些解析会失效，数据库里也会出现两种语言。所以服务端照旧返回中文，前端显示时按句式翻译，报错在请求出错时统一翻译。

**数据值不翻译**：存进数据库、发给服务端或拿来比较的中文（如数据源分类、关键词建议的分组）保持原样，只在显示时翻译。自动改写后用中文回归测试和英文页面扫描两道检查，扫描发现的两处比较错误（分组、分类）已改。

做法上：各列表把勾选的内容登记给页面，页头的按钮把它们加起来；同一页几个列表一起勾，合成一个任务（GitHub 的 Issues 和 Discussions 本来就常一起看）。底部浮出条只保留保存、导出、删除这类管理列表的操作：这些是整理数据，不是交出工作，和“交给 Agent”分开放。

## 2026-10-08 — 一种样子只放一个层级：数字用卡片，状态用清单

小卡片做完后，用户仍觉得右栏和顶部冲突：两处都是带数字的方块，分不出该关注哪部分。参考常见产品的首页（Stripe、Shopify 后台、Google Search Console 概览、Vercel、Linear），通行做法是一种样子只用在一个层级：关键数字用卡片，待办和状态用一行一句话的清单，严重程度靠左边的小圆点和颜色，而不是再放一组大数字。用户确认后：顶部指标卡回答“整体怎么样”，是页面上唯一的大数字；右栏改名“需要留意”，每项写成一句话（数字加粗在句中），要处理的排前面、带琥珀色圆点，其余灰字。没选的两条路：并进“今天的变化”（那里是 AI 的结论，混进数据状态会分不清哪些是 AI 建议的）；塞进指标卡当小字（卡片变挤，审计问题这类数字也没有涨跌可画）。

## 2026-10-08 — 本机 Agent 装成后台程序，页面推荐这种方式

用户的 Agent 早上离线：运行 `start` 的终端窗口没了，程序跟着停了。只靠“重新连接”给出启动命令，下次关窗口、重启电脑还会离线。参照 NocoProject（添加电脑的命令是 login 后接 `daemon install`，装成 launchd 服务），本机 Agent 加 `install-service`，装成当前用户的 LaunchAgent。用户确认方案：添加电脑和重新连接都以 `install-service` 为主命令，`start`（窗口别关）写在小字里给不是 Mac 的电脑；Linux（systemd --user）以后再做。密钥失效时服务停下而不是每 30 秒重试：页面上点了断开，就该真的停。

## 2026-10-08 — Agent 页显示电脑怎么运行

装好后台服务后，用户在 Agent 页看不出这台电脑断了能不能自己连回来：重新连接只在离线时出现，在线时页面和以前一样。给了两种改法：显示运行方式并给终端里运行的电脑“设为后台运行”，或在线时也一直显示“重新连接”。用户选前者：在线的电脑标“后台运行”（蓝色，表示在运行）或“在终端里运行”加按钮，离线的照旧“重新连接”。运行方式由 `start` 报告，`status`、`login` 不带，免得在终端里查一下状态就把页面改成“在终端里运行”。终端里的 `start` 发现后台服务接手后自己停下，避免同时跑两个 Agent。

## 2026-10-08 — Agent 页的电脑和在线 AI 用同一种卡片

用户指出 Agent 页很割裂：电脑是灰色表头加一行工具，状态是自己画的小块，工具后面是绿字“可用”；在线 AI 是白底卡片、带圆点的“可用”标签。按产品其他地方（数据接入的卡片、在线 AI 卡片）的写法统一成一种卡片，做成共用部件 AgentCard：Agent 头像、名称和一个状态标签、一行灰字、信息栏、按钮。用户确认示意图：电脑的状态也叫“可用”（在线且有编码工具才算），和在线 AI 用同一个词；“后台运行”从标签改为信息栏里的值；信息栏平时是普通文字，只有出问题时用琥珀色标签。
