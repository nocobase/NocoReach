# 新渠道自动适配

本次实现接收采集器原始记录的通用入口。它不要求市场人员配置字段，不按渠道名选择算法，也不包含为任意网站自动开发采集器的能力。

## 接入流程

采集器在取得数据后，通过已认证的 `POST /api/nocoreach/nrAutomaticSources/ingest` 提交项目、稳定渠道标识、显示名称、采集时间和原始记录。路径需加部署应用前缀。管理员可写入，成员可通过 `list` 读取本项目的适配结果；沿用应用的认证和项目检查。一次最多 500 条／1 MB，每个项目最多 20 个渠道。管理员可通过 `disconnect` 提交 `projectId` 和 `channelId` 停止该来源参与分析，规则设置与历史素材保留；再次提交有效采集批次会重新接入。

```json
{
  "projectId": "1",
  "channelId": "research-stream",
  "name": "新渠道示例",
  "collectedAt": "2026-10-15T00:00:00Z",
  "records": [
    {
      "article": {
        "headline": "示例内容",
        "permalink": "https://example.org/story/42"
      },
      "stats": { "total_likes": 340, "total_views": 23000 }
    }
  ]
}
```

这是采集器的数据交付协议，不是用户填写的字段映射表。`channelId` 标识连接实例，换数据范围时采集器应使用新实例标识。请求时间必须是真实采集时间，不能把导入时间冒充历史数据的采集时间。系统不会主动抓取提交的 URL。

## 自动识别与校验

1. 遍历有限深度的原始对象，识别标题、原文链接、累计播放量与点赞量；支持嵌套字段、常见命名形式和中文字段名。
2. 采集器若带有原始接口的字段说明，可用 `fieldDescriptions` 随批提交。非标准字段由已配置的在线模型提出映射。仅向模型发送字段路径、说明和样本类型，不发送正文或样本值。
3. 模型只能返回字段选择，不能返回执行代码。服务端验证字段存在、说明引文、累计指标语义及逐条值；每日增量、比例、模糊数量、冲突别名、非法 URL、未来采集时间不作为有效证据。
4. 有可靠内容就自动启用新发现规则，有可靠指标就自动增加对应门槛规则。未知字段不要求用户配置；无法确定时跳过，采集器后续提交新的说明或样本会重新识别。模型不可用时仍处理已明确识别的字段；完全无法识别内容时返回明确错误并保留旧数据，不宣称接入成功。
5. 持久保存适配结果和证据，按项目生成动态规则目录。原有参数、开关、自然语言修改、版本冲突检查和每日信号计算均使用动态目录。指标在某个批次缺失时保留规则和设置，但跳过该批次的判断。

字段说明来自采集器可读取的接口文档或 schema，不要求市场人员编写。没有字段说明且命名不明确的数据，目前不能可靠自动解读；不以模型猜测补齐。当前模板只涵盖内容发现和累计互动门槛，不包含任意业务数据、文本需求分析或增长判断。

## 数据与并发

每个渠道保存最新批次和最多 20,000 个内容 URL 的首次发现记录，避免内容暂时消失再出现被当作新内容。超过边界会拒绝更新，不静默清空历史。较旧批次不能覆盖较新批次。按项目使用与规则设置相同的数据库事务锁；模型推理在锁外执行。失败批次不会覆盖有效记录，不同项目不共享规则或样本。

## 验证范围

`tests/nocoreach/automatic-sources.test.ts` 使用随机渠道标识和未编写专用适配器的嵌套数据，在真实 SQLite 数据库中验证接入、持久化、动态目录、规则修改、每日信号、重复接入及项目隔离。AI 分支用受控模型输出验证，不代表已验证真实模型准确率或真实外部渠道采集。模拟环境的该模型操作返回空映射，无真实请求回退。

本地预览新增“新渠道示例 · 自动识别”，其规则由实际识别函数和规则模板生成，非手工填写；预览本身仍是演示数据。生产上线与真实连接器端到端验收尚未进行。
