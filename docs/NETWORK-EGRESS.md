# 出网设置设计（自托管）

> 状态：已确认。第 1 步（全局代理）已实现，其余按“实现顺序”逐步开发，每一步可单独发布。

## 1. 背景

NocoReach 只以自托管形式推出。用户把应用部署在自己的服务器上，服务器所在网络决定了它能否访问各数据来源。常见的受限情况有：

- 服务器在公司内网，出网流量必须经过公司代理，直连会被防火墙拦截。
- 公司代理会检查 HTTPS，换用公司自己的证书，NocoReach 校验证书时会失败。
- 服务器在中国大陆，GitHub、Google、YouTube、Reddit、X 等服务的连接会被中断或超时（如 Skill 导入时出现 `read ECONNRESET`）。

现有的“网络 Profile”是为了让数据采集能连通而做的：可以保存多个代理，并按“项目 × 数据接入”逐个选择，未选择即直连。底层实现完整（统一出站层、凭据加密、失败不回退直连、公网地址校验），但对用户来说步骤多、概念多：新建项目要重新选择，Skill 库等不属于数据接入的功能没有地方可选，失败时只显示原始错误。

## 2. 思路：参照 n8n 和 Grafana

| 产品                                                                                                              | 做法                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| [n8n](https://docs.n8n.io/deploy/host-n8n/configure-n8n/basic-configuration/use-environment-variables/deployment) | 整个服务一个代理（`HTTPS_PROXY`），`NO_PROXY` 排除少数地址；公司证书通过 Node 的 `NODE_EXTRA_CA_CERTS` |
| [Grafana](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/proxy/)                         | 整个实例一个代理，各数据源只有“是否走代理”一个开关                                                     |

NocoReach 采用同样的结构：**整个应用一个代理，数据接入只有一个开关**。区别在于代理在界面上配置，而不是改环境变量，因为 NocoReach 的使用者不一定是运维人员。

## 3. 界面

### 3.1 设置 → 网络

替代现有的“网络 Profile”页面，只有一张表单：

| 字段     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 代理地址 | 支持 `http`、`https`、`socks5`、`socks5h`。留空表示直连      |
| 用户名   | 可选                                                         |
| 密码     | 可选，加密保存，不返回浏览器；已保存时显示“已保存，留空保留” |

操作：**保存**；**测试** 在第 2 步加入。

“测试”从服务器分别访问几项主要服务（GitHub、Google、YouTube、DataForSEO、npm），对每项显示“可用”或“不可用”及原因（连接被重置、超时、证书不受信任等）。结果只在页面上显示，不保存。

页面底部用 ⓘ 说明：

- AI 模型调用、Runner、浏览器采集器不经过这里的代理。
- 公司代理会检查 HTTPS 时，请在部署时设置 `NODE_EXTRA_CA_CERTS` 指向公司根证书（链接到部署文档）。

### 3.2 数据接入详情

设置了代理后，数据接入详情的“高级”里出现一个开关：**通过代理访问**，默认打开。关闭后，这个接入在当前项目里直连。未设置代理时不显示。

现有的“网络出口”下拉框和“应用到本项目全部接入”按钮删除。

### 3.3 连接失败提示

统一出站层识别连接类错误，按原因给出提示，不再显示原始错误：

| 情况         | 提示                                                                                                     | 操作           |
| ------------ | -------------------------------------------------------------------------------------------------------- | -------------- |
| 直连失败     | 服务器连不上 github.com（连接被重置）。服务器所在网络不能直接访问外部服务时，需要在“设置 → 网络”配置代理 | 去网络设置     |
| 代理失败     | 通过代理连不上 github.com（连接超时）。请检查代理是否可用；未切换直连                                    | 去网络设置     |
| 证书不受信任 | github.com 的证书不受信任。如果公司代理会检查 HTTPS，需要在部署时添加公司根证书                          | 查看部署说明   |
| Skill 导入   | 以上提示之外，再提示可以把 Skill 文件夹下载到本地，用“上传文件夹”导入                                    | 改用上传文件夹 |

## 4. 规则

- **选择顺序**：设置了代理，且该接入的“通过代理访问”打开 → 走代理；否则直连。代理失败时报错，不回退直连。
- **适用范围**：所有经过统一出站层的请求，包括各数据接入的采集、依附于接入的功能（知识链接、关键词建议、项目图标、来源发现等）和 Skill 填链接。依附功能沿用现有约定，跟随对应接入的开关（多为“网站内容”；Skill 的 GitHub 链接跟随 GitHub）。
- **不经过代理**：在线 AI 模型调用（由 NocoBase 框架的 agents 插件发出，NocoReach 无法控制）、Runner（运行在用户自己的电脑上）、浏览器采集器（使用采集器所在电脑的网络）。
- **证书**：校验始终开启，不提供“忽略证书错误”。需要信任公司根证书时，使用 Node 自带的 `NODE_EXTRA_CA_CERTS`。
- **域名解析**：公开抓取目前先在服务器上解析域名、校验公网地址，再通过代理连接。内网 DNS 不解析外网域名、解析结果被篡改，或服务器开着代理软件（198.18.x.x）时会失败。后端改为走代理时经代理解析域名，仍保留公网地址校验；之后 `NOREACH_PUBLIC_DNS` 不再是必需配置。具体做法待实测后确定，界面上没有变化。
- **模拟数据部署**：模拟机制仍基于现有的 Profile。启用模拟插件的部署里，“设置 → 网络”仍显示 Profile 列表，数据接入里仍按接入选择模拟 Profile；全局代理和“通过代理访问”开关只在正式部署出现。

## 5. 不做

- 多个代理、按数据接入选择不同代理（如给 Reddit 单独配住宅代理）。有真实需求后再加。
- 按地址设置“不走代理”。NocoReach 只访问公网服务，内网地址本来就会被拦截，数据接入上的开关已能覆盖需要直连的情况。
- 证书管理界面、NTLM 和 Kerberos 认证、访问内网地址、第三方镜像。
- 读取服务器的 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，避免界面之外出现第二个配置来源。

## 6. 升级

底层仍是现有的 Profile 和“项目 × 接入”选择，只增加“全局代理”和“该接入直连”两个标记。升级时：

- 没有真实代理：全局代理为空，行为不变。
- 只有一个真实代理：设为全局代理；原先未选它的接入关闭“通过代理访问”，保持原来的直连。
- 有多个真实代理：使用最多的那个设为全局代理，其余照上一条处理；原先使用其他代理的接入会改为走全局代理，名单写入服务端日志。
- `NODE_EXTRA_CA_CERTS`、`NOREACH_PUBLIC_DNS` 已有的配置继续有效。
