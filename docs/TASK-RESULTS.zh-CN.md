# Agent 成果提交与恢复

Agent 执行结束后，NocoReach 会检查成果格式与当前任务状态。正文已经写出，不代表成果已经通过校验或人工审核。

## 新任务如何提交成果

具备任务草稿权限的 Agent 可以使用 `nocoreach task result --content-file result.json`，提交完整的成果 JSON。命令只对当前任务运行开放，不接受其他任务或项目的标识。

格式错误会立即返回具体字段。Agent 应保留已经生成的正文，只修正格式，最多再尝试两次。提交成功后，同一份成果可以重复提交；不能覆盖为另一份成果。成果要等 Runner 正常完成后才进入任务流程，仍需负责人审核。取消或执行失败不会自动采用暂存成果。

网页来源填写完整的 HTTP/HTTPS 地址；任务材料填写材料类型，不要伪造网页地址：

```json
{
  "ok": true,
  "content": "完整的 Markdown 正文",
  "report": {
    "kind": "content",
    "sources": [
      { "title": "项目知识", "material": "knowledge" },
      { "title": "参考网页", "url": "https://example.com/article" }
    ],
    "asOf": "资料截至 2026-10-16",
    "uncertainties": []
  }
}
```

`material` 可以是 `context`（任务背景）、`sources`（数据与来源快照）、`knowledge`（项目知识）或 `skills`（技能快照）。它们均属于本次运行，页面不会把本地文件路径显示为可点击链接。研究任务使用 `kind: "research"`，社区回复使用 `kind: "communityReply"`；具体以任务要求为准。

## 已经失败的任务如何处理

如果当前步骤最近一次研究或大纲运行因成果格式失败，任务页会提供“重新校验成果”。负责人或管理员点击后，系统复用保存的最终回答，兼容已知材料引用和运行说明后缀，再重新校验。

校验通过后，成果进入人工审核。原执行失败记录仍保留，并新增恢复操作记录；系统不会重新调用 Agent，也不会自动批准成果。

仍不合格时，页面会说明具体原因，可以重试任务或自行完成。任务已取消、已归档、步骤或负责人发生变化、已经生成新成果，或有新的运行时，不能恢复旧成果。代码修改、合并和回退操作不提供此恢复方式，以免重放有副作用的操作。
