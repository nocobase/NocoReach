# 自动运行

“设置 → 自动运行”列出 NocoReach 在调度插件上自动运行的工作。目前只有“每日分析”：每天在设定时间读取所有项目的最新数据，由 AI 写出本期观察和建议，更新到“洞察”和“机会”。卡片上写明每天几点运行、按哪个时区、上次结果和下次时间。

其他自动工作（Google、GitHub、社区等数据同步，排名跟踪、趋势、竞品动态的每周检查）按项目运行，在“数据接入 → 数据健康 → 查看同步状态”里查看，表格的“频率”列写明每天、每周或手动。这些频率由数据源的更新节奏和额度决定，不能修改。

## 修改每日分析时间

点卡片上的“修改时间”，填写每天的时间并选择时区，然后保存。时区可以搜索城市，例如 `Shanghai`、`New_York`，也可以选择 `UTC`。保存只调整每日分析，从下一次开始生效；刷新或服务重启后仍保留。已暂停的每日分析保存后仍然暂停。

多数数据源在 UTC 零点后同步（北京时间约 08:00）。弹窗里会按所选时区提示这个时间，分析放在它之后才能用上当天的新数据。

卡片上的“上次”和“下次”按浏览器时区显示；浏览器时区和每日分析时区不同时，卡片下方会注明。

## 其他操作

- **运行记录**：从右侧打开，按项目名列出每次运行的结果，失败时写明原因。
- **⋯ → 立即运行**：现在为所有项目分析一次，今天已分析成功的项目会跳过。每天的时间不变。
- **⋯ → 暂停 / 开启**：暂停后不再自动运行，已经开始的这次会跑完。
- **⋯ → 技术细节**：调度插件看到的执行计划（cron）、时区、调度状态、定义状态、执行目标和触发次数，用于排查问题。

## 夏令时和补跑

夏令时沿用现有调度规则：纽约春季不存在的 02:30 顺延到 03:30；秋季重复的 01:30 在持续运行时通常只取第一次。停机恢复可能先补发旧计划，再触发第二次，因此不保证全局只产生一个调度事件。每日分析按任务当地日期跳过当天已分析成功的项目；失败后的重试规则保持原样。

每日分析当天漏跑后，在计划时刻过去至少 15 分钟时补偿。修改配置不会补跑修改前的计划时刻；跨日判断也采用任务时区。
