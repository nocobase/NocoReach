# GitHub 项目发现

在 **接入点 → GitHub 项目发现** 中配置规则，可以持续发现可能使用某个框架或 SDK 的公开仓库，并查看匹配证据。

## 开始使用

1. 配置可搜索公开代码的 GitHub token。也可以复用当前项目已经保存的 GitHub token，无需先接入 GitHub Traffic。
2. 点击 **使用 NocoBase 3 预设**，或新增一条规则。
3. 检查搜索条件、依赖版本、文件和 JSON 字段条件。可以先预览，最多查看五条样本；预览不会保存仓库。
4. 保存规则并执行扫描。在 **GitHub → 项目发现** 查看结果。

NocoBase 3 预设检查 `@nocobase/app-server` 的 3.x 版本范围、服务端与客户端运行时文件，以及 `package.json` 中的 `nocobase.templateKind: app`。这些条件可以编辑，项目结构不同的应用可能需要调整规则。

## 自定义规则

| 设置     | 填写方式                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------ |
| 搜索条件 | 每行一条，`repo:` 表示仓库搜索，`code:` 表示代码搜索，最多五条                                   |
| 依赖     | 每行 `包名 \| 版本范围`，例如 `@nocobase/app-server \| >=3.0.0-0 <4.0.0-0`                       |
| 文件     | 每行 `相对路径 \| 必须包含的文字`，不填文字时仅检查文件是否存在                                  |
| JSON     | 每行 `相对路径 \| 点号分隔的字段 \| 精确值`，例如 `package.json \| nocobase.templateKind \| app` |
| 排除范围 | 每行填写一个拥有者或 `拥有者/仓库`                                                               |
| 扫描范围 | 可选择包含 fork、归档仓库和模板仓库，默认均排除                                                  |
| 扫描频率 | 每天或每周，也可以手动执行；每批检查 5–50 个候选位置                                             |

依赖、文件和 JSON 条件必须全部匹配。依赖条件读取 npm 的 `dependencies`、`devDependencies` 或 `optionalDependencies`；声明的版本范围必须完全处于要求的范围内。无法解析的版本声明保留为候选。代码搜索命中子目录的 `package.json` 时，会在对应应用目录中验证条件。

每个项目最多保存十条规则和 2,000 个仓库。扫描会定期复查已保存的仓库，并在限流或超时后保留进度。修改规则会将该规则旧的匹配结论重置为候选，后续扫描重新验证。暂停规则保留结果；删除规则会移除该规则的匹配，仍匹配其他规则的仓库会保留。

## 查看和整理结果

- **已验证**：符合一条规则的全部证据条件。
- **候选**：搜索找到了相关仓库，但证据条件尚未全部满足。
- **仅提及**：规则没有设置证据条件，不能据此判断实际使用。

点击仓库查看依赖版本、文件与 JSON 字段的期望值、实际值和 GitHub 链接。证据链接固定到扫描时的提交，便于复核。可以确认、忽略或收藏结果；这些人工标记不会改变自动验证结论。

列表支持关键词、规则和状态筛选，以及 Star、仓库创建时间、首次发现时间和最近检查时间排序。首次发现时间指本应用发现该仓库的时间。

## 结果范围

GitHub 搜索存在索引、结果数量和请求频率限制，不能保证找到所有使用者。界面会提示部分覆盖、限流和存储上限；详见 [GitHub 搜索 API 文档](https://docs.github.com/en/rest/search/search#about-search)。公开仓库也不一定采用开源许可证，复用代码前应查看其许可证。

有 GitHub 数据权限的成员可以查看、扫描和整理结果；规则和凭据由有接入点配置权限的管理员管理。凭据加密保存，不会在状态或结果中返回。
