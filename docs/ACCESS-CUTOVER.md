# 第一阶段授权切换与回退

本说明用于演练和上线准备。生产维护窗口、观察期和操作责任人尚未确认；不能直接按本文安排停用或通知。第一阶段同时迁移成员并停用旧无范围密钥，不能先上线角色迁移、再等待后续页面补权限检查。

## 切换前

1. 明确发布版本、数据库类型、备份恢复方式、当前系统管理员及至少一名有效业务管理员。保留可登录的系统管理员入口，并在隔离环境演练整库恢复。
2. 在旧版本上盘点凭据 ID、所属身份、配置、有效期、最近使用时间和集成用途，禁止导出秘密、哈希、会话或凭据文件。新版本的受控 `GET /api/nocoreachKeys/inventory` 仅提供安全元数据；可在备份的隔离演练实例使用。最近无使用记录不能视为无人使用。
3. 由维护者认领每个 CI、脚本、Runner、外部调用及低频定时集成，记录维护者、最小操作和项目范围、换发/退役决定、验证方式。Runner 注册凭据、OAuth 和普通登录会话需与默认 API 密钥分别识别，不批量误删。
4. 获批后通知各维护者停机影响、换发操作、安全交付渠道、预计停用时间及验收责任。尚未完成认领或换发的集成应推迟切换；只有负责人明确接受停用才可关闭该项。本文不代表已取得这些确认。
5. 使用脱敏备份演练启动迁移：核对旧管理员/成员的实际业务访问、未加入账号拒绝、普通框架 member 无权、多个角色组合及移除立即生效、最后管理入口保护、服务身份不出现在成员和负责人中。未知旧角色或账号缺失会阻止启动，应先修复真实数据问题，不能跳过迁移。

## 维护窗口内

1. 暂停业务写入和集成调用，备份完整数据库、当前发布物和配置版本，记录恢复点。先在演练环境执行同一流程并确认恢复用时。
2. 部署后由新迁移建表；应用启动时在同一事务映射成员权限集、停用默认配置的旧无范围密钥并写入迁移标记。失败全部回滚，应用不对外就绪。重复启动不重复迁移；旧 nr-members 只作为备份证据保留，不是新授权来源。
3. 登录系统管理员，通过受控后端换发：`POST /api/nocoreachKeys`，明确个人或组织归属、最小角色和范围、期限（默认 90 天，可选 1–365 天）。组织钥使用独立服务身份，不依赖创建者继续任职；个人钥随人员资格收回。新秘密只在响应中显示，使用安全渠道交付，不贴到议题、日志或截图。
4. 更新集成配置。轮换通过 `/api/nocoreachKeys/rotate`，提交成功后旧秘密立即失效，没有宽限期；停用使用 `/revoke`。停止服务、密钥轮换和更新集成配置需由维护者协调顺序。
5. 逐项执行真实最小业务动作及越界拒绝：正确项目/动作成功，另一项目和管理动作拒绝；系统管理员窄钥也被限制。确认过期、停用、旧秘密失败，混用 cookie 不提升权限，账户接口与通用签钥端点不能绕过。异常可查 `/events`，禁止记录秘密。
6. 主动演练低频任务，或取得维护者明确退役确认。各项记录新 key ID、动作/范围、通过时间及责任人，不记录秘密。全部完成或取得负责人接受的停用决定后才恢复业务，并按另行确认的观察期检查错误及维护者反馈。

## 拒绝和回退

旧无范围、过期或停用密钥返回认证失败（401）。有效密钥超出动作/项目范围返回权限拒绝（403）；隐藏对象存在性时沿用 404。不要通过恢复无范围重签接口解决错误。

切换失败优先修复或换发。确需回退时，保持调用及写入暂停，使用维护窗口开始时的完整数据库备份与对应旧发布版本一起恢复，并重新核对账号、业务数据、密钥和系统管理员入口。只执行新表的 schema down 无法恢复框架角色和已停用凭据；只切回旧代码也不能保证原能力。备份恢复会恢复旧密钥风险，恢复访问必须由上线责任人明确接受并控制入口。

若已恢复业务并产生新写入，回滚会丢失恢复点后的数据及审计，必须先评估导出/合并及取得负责人对损失的明确决定。不得静默回滚数据库。新版本保留的旧成员快照并不包含上线后角色修改，不可用它覆盖新权限并声称无损回退。

本阶段不提供邀请与完整密钥自助页面。邀请/角色页面、邮件及邀请异常路径由第二阶段完成；自助密钥页面由第三阶段完成。生产切换、邮件和真实集成验证均尚未执行。
