# 文章发布

写博客、改已有文章这类任务，可以把审核通过的文章直接发布到“发布目标”（CMS、文章接口或仓库里的文章文件），不再通过网站仓库的 PR 交付。选题、大纲、写作、修改、审核这些步骤都不变。改代码、改页面布局的任务仍然走 PR。

开发说明见 [ARTICLE-PUBLISHING.md](ARTICLE-PUBLISHING.md)，文章接口协议见 [ARTICLE-API.md](ARTICLE-API.md)。

## 发布目标的三种类型

| 类型         | 适用场景                                                   | 能否保证不覆盖他人修改                                             |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| NocoBase API | NocoBase 搭建的 CMS，或以后自建的 NocoBase 文章模块        | 写前复核：发布前重新读取并比对，极小概率会覆盖他人在同一瞬间的修改 |
| 文章接口     | 按 [ARTICLE-API.md](ARTICLE-API.md) 实现了接口的网站或 CMS | 可以保证                                                           |
| Git 文件     | 没有 CMS，文章就是仓库里的 Markdown 文件                   | 可以保证                                                           |

## 连接 nocobase.com 的 CMS

1. 在 CMS 中新建一个专用角色，只授予 `articles` 集合的查看、新建、编辑权限，再为这个角色创建 API key。不要使用管理员账号的密钥。
2. 在 NocoReach 中打开“数据接入 › 博客 CMS”（在“Agent 修改与发布”分组里），点“新建发布目标”：
   - 名称：例如“NocoBase CMS”；类型：NocoBase API；地址：`https://cms.aliyun.nocobase.com`；访问密钥：第 1 步的 API key。
   - 高级设置里已有默认的字段映射（`title`/`title_cn`/`title_ja` 等），按下面补上页面地址和导出设置。同一种语言的页面有几种地址时（nocobase.com 的英文文章既在 `/blog/{slug}/`，也在 `/en/blog/{slug}`，Search Console 记的是前一种），把它们都写进一个列表，第一个是链接和发布后检查用的地址：

```json
{
  "collection": "articles",
  "locales": ["en", "zh", "ja"],
  "fields": {
    "id": "id",
    "slug": "slug",
    "version": "updatedAt",
    "status": {
      "field": "status",
      "published": "published",
      "draft": "drafted"
    },
    "locales": {
      "en": {
        "title": "title",
        "description": "description",
        "body": "content"
      },
      "zh": {
        "title": "title_cn",
        "description": "description_cn",
        "body": "content_cn"
      },
      "ja": {
        "title": "title_ja",
        "description": "description_ja",
        "body": "content_ja"
      }
    }
  },
  "pages": {
    "en": [
      "https://www.nocobase.com/blog/{slug}/",
      "https://www.nocobase.com/en/blog/{slug}"
    ],
    "zh": "https://www.nocobase.com/cn/blog/{slug}",
    "ja": "https://www.nocobase.com/ja/blog/{slug}"
  },
  "downstream": {
    "repo": "nocobase/website",
    "branch": "main",
    "files": {
      "en": "content/articles/{slug}/index.md",
      "zh": "content/articles/{slug}/index.cn.md",
      "ja": "content/articles/{slug}/index.ja.md"
    },
    "metadata": {
      "path": "content/articles/{slug}/metadata.json",
      "keys": {
        "en": { "title": "title", "description": "description" },
        "zh": { "title": "title_cn", "description": "description_cn" },
        "ja": { "title": "title_ja", "description": "description_ja" }
      }
    },
    "exporter": { "name": "NocoBase-CMS" }
  }
}
```

3. 保存后点“测试连接”，能读到一篇文章即可。网站仓库是公开仓库，“导出仓库令牌”可以留空；如果 GitHub 匿名请求被限流，再填一个只读令牌。
4. 发布后页面要等 CMS 每小时一次的同步导出到网站仓库、网站重新部署后才会更新。任务会显示“等待导出”，导出完成后自动检查页面。

文章通过 CMS 的接口写入，和编辑在 CMS 页面上点“保存”走的是同一套接口：权限、字段校验和“数据表事件”工作流都照常生效。只绑定在页面按钮上的“操作后事件”工作流（例如“刷新文章缓存”）默认不会触发；需要时，在高级设置里加上 `"triggerWorkflows": ["<工作流 key>"]`。上线前请先实测一次。

## 在任务中使用

- **按做法选择发布目标**：管理员可以在“文章发布”设置里的“按做法选择发布目标”卡片中，为每个带改动步骤的做法选择默认去向：跟随默认目标、某个发布目标，或“网站源码仓库（PR）”。例如写博客发布到 CMS，改文档页面走 PR。
- **开始任务时**：只要做法里有改动步骤，开始卡片就列出“要改的页面”，并用一行写明在哪里改，一般不需要选择。
  - 交给 Agent 时，任务会带上涉及的全部页面：网站审计的问题页面、搜索表现和访问里勾选的页面、关键词的排名页面、页面详情等。卡片先列前 3 个，其余点“还有 N 个页面”展开。
  - 系统按页面地址和发布目标配置的页面地址规则，判断每个页面在哪里：发布目标里的文章写“博客文章 · 在 NocoBase CMS 里改”，并显示文章标题和语言；其他页面写“网站页面 · 改网站代码，提 PR”。还没接入网站源码仓库时，卡片会提示先去接入，不会让你去选文章。
  - 地址规则对不上时（例如 CMS 按 `/en/blog/{slug}` 配置，Search Console 里的地址是 `/blog/{slug}/`），会把地址最后一段当作 slug 再找一次。由 CMS 导出到网站仓库的文章，即使没找到，也不会改网站代码，而是请你搜索选择文章，搜索框里预先填好 slug。
  - 写博客默认是新文章，写“新文章 · 发布到 NocoBase CMS”。
  - 去向旁边有“更改”，例外情况下可以改选发布目标、搜索其他文章或改用 PR。
  - 任务没有对应页面时（例如新建任务、在对话里交过来），卡片问“要改哪个页面？”，在一个搜索框里同时搜网站页面和博客文章。选中的页面决定在哪里改；不针对某个页面的改动，点“更改改动方式”。
  - 页面分在两处时（少见），这个任务改页面多的那一处，卡片上一行写明其余页面，例如“另外 2 篇博客文章不在这个任务里”。点“单独建任务”，每篇文章各建一个任务，其余网站页面合建一个，做法和任务说明沿用这个任务。建好后这一行改写成这些任务的编号，可以点进去；它们也列在“关联任务”里。
  - 同一个机会里指向同一篇文章的几个地址，只建一个任务。
- **网站源码有多个仓库时**：在“数据接入 → 网站源码”里，每个仓库写明负责哪些网址（一个网址，或网址加路径，例如 `docs.nocobase.com`、`nocobase.com/docs`），同一个网址只归一个仓库。开始卡片的“改到哪”把这些仓库（开 PR）和发布目标（直接发布）放在一个下拉框里，按任务页面的网址自动选负责它的仓库，并写明是按哪个页面选的；页面不归任何仓库，或分属不同仓库时，需要你手动选一个。任务开始后一直用这个仓库开 PR、合并和撤回，之后改仓库设置或移除仓库都不影响它，任务的“属性”里会显示改动的“仓库”。
- **同时发布到多个目标**：有两个以上发布目标时，可以在“也发布到”里勾选其他目标，最多再选 4 个。Agent 只写一份稿件，只审核一次。其他目标按相同的地址（slug）匹配：已有这篇文章就更新，没有就新建。某个目标没有的语言或字段（例如只有英文的目标）会跳过，审核时会显示“不含：…”。开始后不能更换目标。
- **多种语言**：发布目标里排在第一个的语言是“主语言”，在发布目标的设置里可以改。开始任务时，“语言”一行默认勾选目标的全部语言；点“更改”可以换这次的主语言，或者去掉不需要的语言。勾选了两种以上的语言时：
  - Agent 先只写主语言，你先审核主语言，这时提的修改意见只改主语言；
  - 主语言通过后（按钮是“通过，开始翻译”），Agent 把它翻译成其他勾选的语言；
  - 翻译交回后，按语言分页签查看全部语言，点一次“通过并发布”，所有语言一起发布。
    开始前就已经开始的任务不受影响，仍然一次写完全部语言。
- **改已有文章的多种语言**：文章原来就有的语言不重新翻译，而是按主语言的改动原地修改。
  - 主语言通过后（按钮是“通过，更新其他语言”），Agent 以每种语言现在的文字为底稿，做和主语言相同的改动：主语言改了标题或摘要，就只改这些；正文只增加、删除或改写对应的段落，其余段落和原来的译法不动。文章还没有的语言仍然整篇翻译。
  - 交回后标题是“已按英语的改动更新中文、日语，确认后一起发布”，打开就在第一个改过的语言的“改动”视图，逐处核对。
  - 某种语言没有改动时，页签上方会写“日语没有改动。”；要写的语言都没有改动时，卡片标题直接写“中文、日语没有改动”，可以点“重新更新”让 Agent 再做一次，也可以在动态里写修改意见，或者只发布主语言（“只发布英语”）。
  - 不想动某个语言，开始时把它去掉。
- **文章用什么语言写**：
  - 文章用主语言写，和项目的 AI 内容语言无关：项目语言是中文、任务说明和大纲也是中文时，英语为主语言的文章照样用英语写，只有给审核人看的说明用中文。
  - 新文章必须有主语言的标题和正文。主语言不是发布目标的第一个语言时（例如选了中文），先写中文，审核通过后再翻译成勾选的其他语言；只勾选了中文，就只写中文。
  - 没有选语言就开始的任务（例如在对话里让 AI 开始），以发布目标的第一个语言为主语言，一次写完全部语言。
  - Agent 写成了别的语言时，提交会被退回，并写明缺哪种语言，例如“新文章必须有英语（en）的标题和正文，这次只写了：中文（zh）。”Agent 会用要求的语言重写后再提交。
- **翻译已发布的文章**：做法选“翻译成其他语言”（原来叫“同步多语言版本”）。开始卡片显示“要翻译的文章”，以及一行“从 英语 译成 日语”。默认从文章已有的第一个语言译成它缺失的语言；如果一种都不缺，就默认译成全部其他语言，用来按原文更新译文。点“更改”可以换文章、原文语言和要译成的语言，缺失的语言旁边标着“缺失”。NocoReach 不知道哪个译文已经过期，需要更新的语言请自己勾选。
  - 只能选已有的文章，也不能同时发布到其他目标；发布目标只有一种语言时，卡片会提示没有可以翻译的。
  - 开始后 Agent 直接翻译，只写勾选的语言，原文不改，也不用再审一遍原文；提修改意见时也只改译文。
  - 审核时按语言分页签查看；原来就有的语言可以切换“预览”和“改动”。点一次“通过并发布”，所有译文一起发布。
  - 页面在网站仓库里（不在发布目标里）时，这个做法照旧开 PR。
- **审核时**：按语言分页签查看每个改动字段的前后对比。可以直接编辑，保存后会生成新版本。目标支持状态时（例如 NocoBase CMS），可以选择“草稿”或“发布”：新文章默认是草稿，只有选了“发布”，审核通过后才会在网站上公开。只有审核通过的版本会被发布；未审核的稿件不会写入 CMS，所以也不会被每小时的导出带出去。
- **发布时**：
  - 发布前会再次读取文章。如果别人在审核期间改了**同一字段**，会提示冲突，两个版本都会保留。点“重新审核”后，会基于最新版本重新确认。别人改的是**其他字段**时，会保留他的修改，只写入本稿改动的字段。
  - 如果网站仓库里这篇文章有**只在仓库里改过**、还没回到 CMS 的内容，也会阻止发布：CMS 导出会把这些内容覆盖掉。请先把仓库里的修改并入稿件。
  - 网络超时这类情况会显示“发布没有完成”。点“重试”时会先核对文章，不会重复写入。
- **多个目标的发布**：各目标分别发布，互不影响，发布卡片上会列出每个目标的状态。某个目标失败时点“重试”，只会重试失败的目标；某个目标有冲突时点“重新审核”，已经发布成功的目标不会重复写入。写新文章时，如果其他目标里已有相同地址的文章，会提示“地址已被占用”，重新审核后改为更新那篇文章。所有目标都保存（需要导出的已导出）后，才开始检查页面。
- **发布后**：14 天内如果 CMS 里这篇文章又被改动（例如编辑用打开很久的旧表单保存），任务上会提示，并可以查看对比。这种情况只能事后发现，不能事先阻止。

## 代码任务与 CMS 管理的文件

配置了导出到 Git 的目标后，代码任务的 PR 如果改了这些文章文件（如 `content/articles/*/index.md`、`metadata.json`），将无法审核通过：这些文件会被 CMS 的导出覆盖，应改用文章发布。已经打开的同类 PR（例如 nocobase/website#185）不要直接合并，请改为文章任务重新发布这些改动。

## 尚存的风险

- NocoBase API 类型是写前复核：从核对到写入之间约一秒的空档里，如果有人保存，他的修改可能被覆盖。概率很低。
- 编辑在发布之前打开、发布之后才保存的旧表单，会覆盖已发布的内容。任务上会提示，但无法阻止。
- 绕过 NocoReach 直接在网站仓库里改的文章，仍可能被 CMS 导出覆盖，这和以前一样。

要完全消除前两条，需要 CMS 在写入时检查版本，例如在数据库层加版本校验。这不在本次改动范围内。
