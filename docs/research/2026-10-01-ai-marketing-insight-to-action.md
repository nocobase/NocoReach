# AI 营销产品如何从洞察走到行动（2026-10-01）

目的：任务流程不能只覆盖“改官网”“写调研”两类。调研主流 AI 营销产品如何组织多种工作类型、谁来执行、人在哪里确认。资料来自各产品官网与帮助文档（通过 agent-reach 的 Exa 搜索读取），只作设计参考。

## 各产品做法

| 产品 | 工作怎么定义 | 谁执行 | 人在哪里确认 | 多种工作类型怎么容纳 |
| --- | --- | --- | --- | --- |
| AirOps | Playbook：一份自然语言文档，分成若干 Section（目标、要用的输入与工具、步骤、产出），可挂 Brand Kit、知识库 | 一个 agent 按 Playbook 从头跑到尾，用工具完成研究、写作、发布 | Section 末尾可加 Human Review 暂停点；全部待审核的事集中在 Inbox | 每种工作就是一个 Playbook（内容刷新、新内容、策略研究等）；Campaign 把“机会 → 行动 → 衡量”串起来 |
| Optimizely Opal | Agent = 工具（能做的动作）+ 技能（行为准则）；多个 agent 可拖成工作流 | 按目的划分的 agent（50+ 预置，可自建） | 内容上线前必须人审核、编辑、批准 | 预置 agent 覆盖内容、合规、报告等，用户用自然语言自建 |
| HubSpot Breeze | Agent 有输入、指令、工具、知识 | 按目的划分的 agent（内容、社交、外联等） | 写入类工具可单独打开“运行前需审核”；社交帖子发布前必须批准 | 新工作类型 = 复制并修改一个 agent |
| Profound | Agent = 工作流模板（内容刷新、FAQ 生成、竞品研究、新文章），节点可拖拽 | 一个 agent 完成研究、写作、发布一整轮 | 每次运行在发布前有批准步骤 | 预置模板 + 自建；闭环跟踪新内容是否被引用 |
| Writesonic Action Center | 机会按影响、信心、成本（ICE）排序，分内容、外部引用、技术三类行动 | 平台内的 agent 执行，部分可一键推到 CMS | 推送与外联前确认 | 一个行动目录覆盖 15+ 种手段；流程统一为 排序 → 执行 → 核实 → 衡量 → 迭代 |
| Jasper | 预置 agent（优化、研究、翻译、个性化）+ Studio 自建工作流 | 按目的划分的 agent | 输出审核后再用 | 新类型 = 新 agent 或工作流 |

## 共同规律

1. **工作类型用“做法模板”容纳，而不是一个阶段机。** 每种工作写成一份说明（目标、步骤、用到的数据与技能、交付物、检查点），数量可以不断增加，用户能复制改写。
2. **一次运行只有一个执行者，靠工具完成不同动作。** 研究、写作、发布都是同一个 agent 调用不同工具；不会把同一件事拆给两个执行者接力。
3. **确认规则统一：写到外部之前必须人批准**（发布到 CMS、发帖、改 CRM）。读取、研究、起草可以自动进行；模板里还可以加额外的检查点。
4. **待确认的事集中在一个收件箱。**
5. **所有工作共用一个生命周期：机会 → 执行 → 确认 → 交付 → 衡量。**

## 对 NocoReach 的启示

- 把“流程”改为“做法”（模板），内置多种常见工作；执行者由做法需要的工具决定：需要改仓库就在本机 Agent 上跑，否则由在线 AI 跑，一个任务不再跨两个执行者。
- “改仓库、合并发布、对外发出”属于写入类动作，统一需要确认；其他检查点由做法自己声明。
