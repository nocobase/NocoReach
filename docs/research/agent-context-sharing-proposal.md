# 方案：本机 Agent 与在线 AI 共享资料

2026-10-03 写，2026-10-08 用户确认三件都做（数据摘要随任务带；每日分析带最近 30 天的任务；审核通过的文档自动存进知识库，分类“Agent 交付”），随时查询和在线 AI 读仓库先不做。已开发，见 SPEC 第 9、10 节。

## 现在各自知道什么

| | 本机 Agent（做任务） | 在线 AI（每日分析、写机会） |
| --- | --- | --- |
| 任务说明、依据里引用的信号 | ✅ | — |
| 项目记忆、知识库、Skills | ✅ | 只有项目记忆 |
| 各数据源的最新数据（搜索词、页面访问、排名、审计问题） | ❌ 只看到任务里引用的那几条 | ✅ 以信号的形式 |
| 做过哪些任务、改了什么、效果如何 | 只看到上一个任务交来的文档 | ❌ |
| 网站源码仓库 | ✅ | ❌ |

两个缺口：

1. **Agent 做任务时查不到数据**：比如“优化商业服务页”，它看不到这页最近的搜索词、点击率、审计问题、关键词排名，只能靠任务里写到的那几句。
2. **在线 AI 不知道 Agent 做了什么**：每日分析可能又推荐刚做完的事，也不会说“上周改的那页，第 7 天点击涨了 26%”。

## 建议做三件小事

```
            ┌───────── ① 每次运行带一份“数据摘要” ─────────┐
 NocoReach  │                                                ▼
  数据 ─────┤                                            本机 Agent
            │                                                │
            └──◄── ③ 接受的分析文档自动存进知识库 ◄──────────┘
                         │
                         ▼
                    在线 AI ◄── ② 每日分析多带“最近 30 天的任务”
```

1. **Agent 每次运行带一份“数据摘要”**（放在仓库外的临时目录，和知识库一样）：
   - 关联页面近 28 天的访问、搜索点击、点击率、平均排名，以及主要搜索词；
   - 这页在网站审计里的问题；
   - 任务里关键词的排名（已保存或排名跟踪里有的）；
   - 这页以前的任务和第 7、28 天效果。
   - 没有关联页面时，只带全站概况和任务里提到的关键词。
2. **每日分析多带“最近 30 天的任务”**：标题、做法、页面、到了哪一步（已上线、观察中、已撤回），以及第 7、28 天效果。规则加一句：刚做完、还在观察的事不再推荐，可以引用效果。
3. **接受的分析文档自动存进知识库**（分类“Agent 交付”，可以删）。在线 AI 和以后的 Agent 都能看到，调研不用重复做。

都不花钱，也不加新的设置项。

## 先不做的

- **Agent 随时查询 NocoReach（MCP 工具）**：更灵活，但要在 Agent 程序里多跑一个服务，还要逐个设计查询接口。先用“数据摘要”，不够用再加。
- **在线 AI 读仓库（GitHub 只读 token）**：每日分析看信号就够了；改了什么从任务记录就能知道，不需要看源码。
