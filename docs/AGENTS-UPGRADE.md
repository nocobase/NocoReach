# Agents 插件调整说明

本次使用 Agents `0.1.0-beta.11`、Runner `0.1.0-beta.9` 和 CLI Client `0.1.0-beta.7`。NocoReach 的应用及 CLI 分发版本为 `1.0.0-beta.68`；模板来源版本没有变更。

## 使用变化

- Runner Agent 来自执行机上报的编码工具和模型，由管理员填写能力描述并启用。在线 Agent 在“Agent → 在线 Agent”标签中配置，Runner Agent 位于同一页面的另一个标签。
- 所有任务都由 Runner Agent 执行，包括研究、草稿、代码修改和 PR 操作。任务中的执行记录统一展示 Runner 运行过程。任务可以指定 Agent，不再提供“项目 AI”配置页面。
- 在线 Agent 仅用于对话，支持读取项目资料、公开网页和在聊天中起草内容，不参与任务运行或成果审核。模型服务仍用于每日分析等应用自身的 AI 调用。参见[在线 Agent 使用说明](ONLINE-AGENTS.md)。
- Runner 通过任务资料读取和草稿暂存能力处理当前任务，受任务参与者、运行状态及业务权限检查约束。成果继续人工审核。
- 插件运行记录由 `agents.runs.retentionDays` 控制保留时间，`0` 表示不清理；应用自有在线聊天记录独立保存。

## 配置与验证

1. 构建应用及 CLI、Runner 分发包，确认版本与本说明一致。
2. 接入 Runner，等待它上报工具和模型，启用发现的 Agent。需要仓库操作时，在 Runner 环境中安装并登录 GitHub CLI，确认仓库访问权限。
3. 在任务中选择 Runner Agent，验证资料读取、成果返回、人工审核、取消和重试。业务任务只通过任务页面重试。
4. 配置聊天模型和在线 Agent，验证项目问答、会话历史与停止生成。未接入指标数据源的项目也可以使用在线聊天。

产品尚未发布，本次不提供旧在线任务、旧 AI 步骤、`startRun` 接口或旧在线记录格式的兼容路径。开发环境应使用新建的任务和对话验收。
