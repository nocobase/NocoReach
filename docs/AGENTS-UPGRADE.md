# Agents 插件升级说明

本次升级使用 Agents `0.1.0-beta.11`、Runner `0.1.0-beta.9` 和 CLI Client `0.1.0-beta.7`。NocoReach 的应用及 CLI 分发版本为 `1.0.0-beta.68`；模板来源版本没有变更。

## 使用变化

- Runner Agent 来自执行机上报的编码工具和模型，由管理员填写能力描述并启用。在线 Agent 则在「Agent → 在线 Agent」标签中配置，Runner Agent 位于同一页面的另一个标签。
- 研究、草稿和在线聊天可使用应用自有的在线执行模块，无需 Runner；代码仓库和 PR 操作使用 Runner。旧流程的在线步骤可显式重试，升级前中断的运行不会自动重放。模型服务继续用于每日分析等应用自身的 AI 调用。参见[在线 Agent 使用说明](ONLINE-AGENTS.md)。
- 升级前的项目默认 Agent 和任务指定 Agent 会变为不可用。请在任务中重新选择执行 Agent；项目默认配置页面已移除。系统不会自行替换执行者。
- 新版自动提供任务资料读取和草稿暂存能力，仍受任务参与者、运行状态及业务权限检查约束，人工审核流程不变。
- 默认保留运行过程记录。插件历史记录可通过 `agents.runs.retentionDays` 配置清理，`0` 表示不清理；应用自有在线记录独立保存，不受该设置影响。

## 上线步骤

1. 暂停新增任务，等待正在执行的任务结束。迁移会取消旧 Agent 的排队运行，不能视为普通滚动升级。
2. 备份数据库、持久化文件及配置，保留上一版发布包。确认备份可恢复后再启动新版。
3. 构建并部署新版应用。项目构建钩子会同时生成 NocoReach CLI 和 Runner 分发包；检查分发清单版本与本说明一致。
4. 更新 Runner 和应用 CLI，确认 Runner 重新上线并上报模型。仓库任务还需在 Runner 所在环境中安装并登录 GitHub CLI（`gh`），确认可访问目标仓库。启用发现的 Agent；在线场景则检查模型服务并配置在线 Agent。然后在任务中重新选择执行 Agent。
5. 旧排队运行取消后，业务同步会将对应任务运行标为失败；确认任务状态和审核要求后，在任务页面手动重试。不要通过通用运行重试接口重放业务任务。
6. 验证研究或草稿任务、资料读取、人工审核、取消和重试。涉及仓库时再验证 PR 创建和审核后的发布流程。

## 历史与回退

上游迁移 `202610240020_ag_runner_agents` 将所有旧 Agent 标记删除并停用，取消其排队运行、撤回待处理请求，并清空聊天默认 Agent。旧 Agent 行、任务快照和历史结果保留用于展示。

降级依赖或执行该迁移的 `down` 不会恢复旧 Agent，也不会恢复被取消的运行。需要回退时，应停止新版并同时恢复上一版发布包及升级前数据库备份；按实际变化恢复持久化文件和配置。恢复后不要自动重放可能已经产生外部副作用的任务。
