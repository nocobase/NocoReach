# 分析方案：本次范围与后续演进

状态：产品原则已于 2026-10-15 确认；多方案页面仍为本地交互预览，以下服务端能力尚待实现。本文是本次实现与验收依据，不表示功能已经上线。

## 已确认的产品原则

- 每个项目最多保存 5 套完整分析方案，包含默认方案；同一时间只有一套当前方案。
- 每套方案包含自己的单条规则、开关、参数和分析配置；新建从标准规则开始，复制保留完整配置，之后独立修改。
- 新建、复制、添加规则使用表单弹窗；启用另一套方案使用确认弹窗。方案操作位于对应方案卡片，规则操作位于具体规则区域，不设置独立“正在编辑”卡片。
- 选择方案仅改变查看和编辑对象；未启用方案的修改不影响当前分析。新建和复制不自动启用。
- 自然语言明确作用于所选方案，生成具体差异后由用户确认；不支持或数据不足的需求不能假装生效。
- 规则发现变化，AI 结合业务知识形成洞察和机会，用户决策后进入执行。规则命中、用户采纳、交付完成、产生效果是四种不同事实。

特别注意：当前信号计算与每日 AI 分析分别读取规则配置。正式多方案实现必须在一次分析开始时读取并固定同一份完整快照，贯穿信号计算、AI 判断和结果保存，不能在途中切换方案后混用两套配置。

## 本次必须实现

### 1. 方案与规则基础

- 项目级持久方案集合、唯一 activeSchemeId、至多 5 套的服务端校验。
- 每次成功修改产生不可变配置版本；分析开始时固定方案、规则目录／执行器版本、参数、观察期限和判断要求。
- 切换与保存使用事务及版本冲突校验。正在执行的分析继续使用开始时快照，下一次分析才采用新配置。
- 自定义规则必须有可执行定义：数据需求、对象范围、判断方式、条件、证据要求和执行器。自由文本本身不算已接入可执行规则。
- 尚未支持的执行方式保存为草稿并解释原因；推荐或生成规则必须先校验，再确认加入指定方案。
- 历史单方案配置迁移为默认方案，保留原有开关、参数、团队背景和观察期限。

### 2. 数据源覆盖与规则可用性

采用“来源实例 → 数据能力 → 规则需求”的关联，不把来源名称直接当作规则能力。

来源实例记录连接状态、同步状态、实际数据字段、覆盖时间、对象范围和更新时间。规则声明所需能力、历史窗口、有效样本和缺失处理方式。来源能力复用必须经过适配器验证，不能仅凭同为“社区”就将不同平台字段直接套入同一算法。

规则页从项目实际来源清单生成覆盖展示，包括没有规则的新来源；保留未接入来源的标准规则，但明确标注状态。

区分以下状态，不能用同一个“无数据”掩盖原因：

- 可运行：所需来源、数据字段、范围及历史满足条件。
- 等待数据积累：已接入，但时间覆盖或样本不足。
- 缺少所需数据：没有满足要求的来源或字段。
- 来源暂停／同步异常：保留规则和历史结果，说明影响。
- 尚无适配规则：来源已经存在，但还没有可执行的分析规则。
- 状态未知：读取来源状态失败，不据此误报未接入。

“规则已开启”与“规则可运行”独立显示。缺数据不等于规则被关闭；没有命中也不等于规则未运行。

新来源接入后：

1. 根据适配器声明的数据能力自动匹配标准规则，默认开启；保留用户对已有规则的开关与参数修改。
2. 展示自动匹配的标准规则，说明分析目的、所需数据和适用范围，不要求用户手动创建基础规则。
3. 用户选择目标方案，预览并确认加入；按规则定义去重，避免接入同类来源后重复创建。
4. 对任意用户自定义来源，本次保证可见、能说明支持程度；不承诺自动生成可执行规则。

### 3. 规则到执行效果的关联记录

沿现有洞察、任务和成果记录补充引用，不创建一套平行任务或成果系统。

| 层级       | 本次应保存的事实                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| 分析批次   | projectId、analysisRunId、schemeId、schemeRevision、不可变完整配置快照、分析时间和数据截止时间         |
| 规则运行   | ruleId、ruleRevision、来源实例引用、数据窗口、状态（命中／未命中／不可运行／失败）和原因               |
| 信号       | 规则运行引用、证据快照及来源；不能只记录会随时间复用的 signal key                                      |
| 洞察／机会 | 所引用信号及分析批次、AI 判断；一次机会可能引用多条规则，不强行归属单一规则                            |
| 用户决策   | 采纳／暂缓／放弃，以及用户给出的原因、时间和操作者；系统行为与用户反馈分开                             |
| 任务／交付 | 保留已有机会、任务、产物、审核及发布记录的关联；PR 合并及其他实际交付条件仍由既有执行流程核实          |
| 效果观察   | 预期目标、指标定义、基线、开始时间、观察窗口、数据覆盖和观察结论；没有可量化指标时允许明确标记不可评估 |

历史数据缺少配置版本时显示“历史版本未记录”，不能拿今天的配置补写成过去事实。方案后续变更不改变旧任务的依据。模拟发布不启动真实效果观察。

反馈分开保存：

- 洞察质量：有价值、不相关、重复、证据不足。
- 决策约束：资源不足、时机不合适、已在处理等。暂缓不等于规则错误。
- 交付事实：完成、审核确认、实际发布。完成不等于有效。
- 效果观察：指标上升、下降、无明显变化、数据不足等。观察结果不能自动作为因果结论。

本次只建立可靠记录和可追溯展示，不自动改写用户规则。业务知识作为判断依据引用，规则配置版本与知识引用分别保存。

## 后续计划

1. 按方案版本、规则及来源查看命中、用户反馈、采纳和效果覆盖；样本不足时不计算误导性“成功率”。
2. 历史试跑：比较新旧方案在同一数据快照上的差异，列出新增和被过滤信号；明确它无法证明未来效果。
3. AI 调优建议：说明依据、样本、预期影响和可能漏掉的机会，用户确认后生成新版本。
4. 更多自定义数据源的能力识别与规则生成，逐类适配和验证后开放，不把任意自然语言视为通用执行器。
5. 扩展非网站类任务的效果观察方式，避免把所有市场动作硬套到 GSC／GA4。

## 实施顺序及验收

先实现服务端方案与不可变快照，再实现来源需求和运行状态，随后补齐跨洞察／任务／成果的关联及反馈，最后接通页面。交互预览只验证使用方式，不替代这些步骤。

- [ ] 旧配置迁移无损；项目隔离、成员读取与管理员修改权限均由服务端执行。
- [ ] 并发创建不会超过 5 套，并发切换始终只有一套当前方案。
- [ ] 分析途中切换或修改方案，当前批次保持旧快照，下一批次采用新版本。
- [ ] 新接入但尚无适配规则的来源会出现；来源清单读取失败显示未知状态。
- [ ] 来源暂停、重新接入、历史不足、缺少必需字段、同类多实例均有明确状态。
- [ ] 推荐规则需确认后加入指定方案；没有可执行定义的规则不进入当前分析。
- [ ] 一条机会关联多条信号／规则后仍可追溯；任务交接、审核、发布和成果页不丢失引用。
- [ ] 规则调整不改写历史依据；旧记录缺失字段不编造；无数据不记为失败或零效果。
- [ ] 未完成交付、未合并 PR、模拟发布不被误当成真实效果观察起点。
- [ ] 反馈原因与执行效果分别保存；尚无足够证据时不生成自动调参结论。
- [ ] 弹窗、焦点、校验、方案隔离、中英文及窄屏交互继续使用现有回归检查。

## 内容渠道通用规则首批实现

`content-rules.ts` 按能力声明生成规则目录与执行判断，`content-source-inputs.ts` 负责渠道字段映射。新渠道提供 `ContentSourceDefinition` 和 `ContentInput` 后可复用执行器，不需要复制平台规则。通用采集入口现已自动识别原始记录和接口字段说明，经过校验后生成项目动态规则，详见 [新渠道自动适配](AUTOMATIC-CONTENT.md)。含义未知的数据不会被猜测为已适配。

首批验证 YouTube、Bilibili、小红书。能力包括首次发现时间、公开播放量、公开点赞数；每种指标单独产生规则实例，沿用现有开关、参数和自然语言调整。原有 36 条规则保持不变，总计 44 条。新增模板默认采集有效期 7 天、首次发现窗口 7 天、播放量门槛 10,000、点赞门槛 100；这些是可调整的初始筛选门槛，不是市场效果标准。

没有时间序列，不生成增长、下降或异常趋势规则；没有评论正文，不生成评论需求规则。累计指标不代表转化，新发现不代表刚发布。规则只提供可追溯的样本证据，后续每日 AI 分析再判断与项目目标的关系。过期、未来时间、缺失或非有限指标均跳过；一个来源读取失败不阻断其他来源。

YouTube 仅分析当前搜索批次的保存记录，保留每项指标自己的时间戳。升级前的记录缺少搜索范围归属，需要再次同步一次；不会删除历史素材。Bilibili 排除旧配置版本的记录，小红书排除旧关键词记录，断开连接的来源不参与计算。数据覆盖弹窗仍为预览，实际项目的逐条可运行状态是后续工作，不能把匹配规则数当作成功运行数。
