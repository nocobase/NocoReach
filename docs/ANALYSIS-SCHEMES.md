# 分析方案

本分支已实现正式页面和服务端能力；尚未合并或部署。

## 使用方式

每个项目最多 5 套完整分析方案，包含默认方案。同一时间只有一套当前方案。点击方案卡片只切换查看和编辑对象，点击“使用此方案”并确认后才切换实际分析。

新建从标准规则开始；卡片上的复制按钮会复制该方案的全部配置和自定义规则，之后独立修改。历史单方案配置自动作为默认方案读取，首次修改时保存为新结构，原有开关、参数、团队重点与观察时间保持不变。

页面保留所有具体规则、开关和参数，按规则能找出的机会类别分成 5 个标签：当下热点、新内容机会、竞品差距、内容优化与当前状况，默认打开当下热点，类别顺序与机会页的筛选一致。前 4 类共 28 条规则，名称与机会页的类型名一致（同为“搜索量上升”的两条分别注明“关键词”和“Google Trends”），每条规则名前显示来源图标，最后一行写来源名称；每个标签下用一句话说明它回答的问题，并链接到机会页对应类别。其余规则不提出机会，只更新洞察里的当前状况和变化，放在“当前状况”下，仍按来源分小标题。自定义规则一律放在当前状况：算不出增长空间，不会成为机会。来源检测状态和最近采集时间统一在数据接入页面查看。默认／已调整摘要包含自定义规则、参数、开关、团队重点和观察时间的变化。

上次分析使用的正是当前查看的方案版本时，每条规则显示“这次 N 条”，这次没有找到的显示 0；证据不足或判断失败的规则显示原因。方案修改后版本改变，数字在下一次分析后再出现。

页面右上角的“让 AI 帮你调规则”打开右侧对话，AI 已读取所选方案的全部规则，并提供“少报一些小波动”等几个常用问题。AI 提出的修改在对话里逐条显示原值和新值，点击“确认修改”后才通过页面原有的保存接口写入，规则页随即刷新；规则在提议之后有变化时，这项修改显示为已过期，不会保存。添加规则弹窗只用于手动填写，用文字描述新规则改在对话里进行。已添加的规则支持重新编辑及关闭。取消和关闭弹窗不会保存规则。

## 每日分析里的 Skill

和做法的每一步一样，每套方案可以选最多 5 个 Skill，在规则下方的“Skill”区块里添加或移除；在 Skills 页面打开某个 Skill，也能用“每天用这个 Skill 找机会”开关加入或移出当前使用的方案，两处是同一份设置。新建项目和已有项目的“默认分析”各自动加入一次 content-strategy、competitors、ai-seo，移除后不会再自动加回；复制方案会一并复制 Skill，新建的空白方案不带 Skill；Skill 被删除时从所有方案中移除。

每次每日分析，每个选中的 Skill 单独调用一次模型：说明里放 SKILL.md 正文，数据是当天已保存的关键词分组、本站页面的 Search Console 数据、竞品页面、问 AI 搜索的问题和社区反复被问到的问题，最多约 1 万 token；每个 Skill 最多提 3 条机会，每条必须引用数据里的具体关键词、页面或问题。服务器核对引用的条目都在当天数据里，再用规则相同的公式算出增长空间和机会类别，模型自己写的数字一律不用；引用不到或算不出增长空间的候选不保留。保留下来的候选和规则找到的变化一起交给每日分析判断，写明是哪个 Skill 找出的。某个 Skill 调用失败只在它那一行显示原因，不影响其他 Skill 和整次分析。

这些调用走“每日分析”那一行选的模型。机会详情的“为什么值得做”下注明“按 Skill … 找出”，链接到该 Skill；交给 Agent 时，这个 Skill 和做法这一步指定的 Skill 合并去重后一起交给 Agent。Skills 页面的“用在”列标出用在每日分析的 Skill，并可按它筛选；详情里显示最近 30 天它找出的机会数和交给 Agent 的数量，链接到只看它找出的机会。

每个 Skill 每天多一次模型调用，输入约为正文长度加上 1 万 token 数据和约 1,500 token 说明。“添加 Skill”弹窗按正文长度估算每个 Skill 每月多用的输入 token。Skill 不会触发新的付费数据查询，也不检查某个 Skill 是否适合找机会。

## AI 与规则执行

对话中的规则调整、页面接口保留的规则草稿与自定义规则判断均通过应用配置的在线模型网关调用；未配置模型会明确报错，不用示例结果替代真实回答。只有模拟环境启用了 mock 插件时才使用隔离的模拟回复。

标准规则继续使用确定性计算。自定义规则使用 `saved-evidence-v1` 执行器，限定来源、条件和证据要求，读取已保存的来源样本及信号。证据候选不依赖内置规则先命中，因此自定义阈值可以宽于标准阈值。输入按来源分配预算，过滤连接密钥字段；模型输出必须引用本次提供的同来源证据，不能自行提供其他链接。

自定义规则分析的是有界样本，不是全量扫描或新增采集任务。缺少历史、字段或事实时记录证据不足；调用或输出校验失败时记录失败，下次分析重试。规则命中只提供候选变化，后续洞察分析再结合项目目标和知识判断是否值得行动，不等同于真实效果。

内容规则逐条检查字段、指标时间与有效数值，不会把“来源有新鲜内容”当作“所有指标都齐全”。旧来源尚未提供完整逐规则数据需求声明时，未检测到变化的完整性状态标为未知，不能据此声称没有机会。

## 新来源自动适配

通用采集入口接收来源名称、记录及可选字段说明，自动识别并验证标准字段，按能力生成可编辑规则，不要求用户配置映射。未知含义、无有效内容标识等情况明确拒绝，不能猜测支持。接入新来源的数据采集仍由连接器或采集调用方负责，自动规则适配不等于能自动抓取任意网站。

首批渠道为 YouTube、Bilibili、小红书，复用首次发现、累计播放量和累计点赞数模板；默认目录包括 36 条原有规则和 8 条内容规则实例。通用入口另用没有专门适配代码的新渠道做 SQLite 验证。详见[新渠道自动适配](AUTOMATIC-CONTENT.md)。

累计指标不代表增长或转化；新发现不代表刚发布。没有时间序列不生成趋势结论，没有评论正文不生成评论需求结论。断开、过期、未来时间及旧查询范围的内容不参与计算。

## 版本、权限与追溯

- 方案集合、配置与自定义规则按项目持久化；读取允许成员，修改与 AI 配置操作仅允许管理员，服务端执行权限校验。
- 方案最多 5 套、自定义规则每套最多 20 条。并发创建、切换、保存使用同一事务锁与修订检查。
- 配置修订绑定方案 ID、版本和规则目录。不同方案即使参数相同，也不能相互套用旧的 AI 修改提案。
- 一次分析先固定方案版本和完整配置，再计算信号、调用模型、保存洞察；分析途中切换方案只影响下一次分析。
- 分析证据包含分析批次 ID、方案快照、规则运行结果及自定义规则引用的证据。洞察进入任务时沿用既有证据上下文，不重新拼接当前方案。
- 旧历史没有版本时不补写推测版本；规则页不把其他方案或其他批次的判断数量混在一起。

## 验证与边界

自动化覆盖旧配置迁移、项目隔离、复制独立性、并发最多 5 套、唯一当前方案、修订冲突、模型输出与引用校验、缺失和过期指标、取消后的迟到回复，以及分析过程中切换方案。

浏览器检查使用正式页面组件和测试 API／模型回复，验证弹窗、复制、选择隔离、规则添加及编辑、对话中的修改确认、取消启用、中文／英文、窄屏与暗色。它不代表已经在 Studio 上调用真实模型验证；本分支未部署，因此线上配置模型的联调仍需在部署后的已登录环境进行。

后续继续完善：旧来源逐条数据需求声明、更全面的自定义样本检索、按方案版本汇总反馈及效果、同一历史数据的新旧方案对比，以及有证据且需用户确认的调优建议。当前不会因采纳或交付就自动调整规则，也不会把缺少效果数据记为零效果。
