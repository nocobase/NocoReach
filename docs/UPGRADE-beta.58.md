# beta.58 升级记录

Default 模板从 `1.0.0-beta.56` 三方合并到 `1.0.0-beta.58`。这是未发布产品的一次破坏性升级，不保留旧 Agent 程序、电脑密钥、轮询执行接口或旧 AI 员工适配。

## 实现与合并决策

- Agent、Runner、模型和用量采用官方 Agents 插件页面，保留插件的权限声明。聊天使用官方 Agent Chat 组件。
- NocoReach 任务以 `nocoreachTask` subject 进入官方运行服务；业务运行与插件运行在同一事务创建，提交后发送事件，按运行 ID 同步状态和成果。任务进度读取官方运行事件。
- 仓库、共享 Runner Agent 的选择仍是项目设置。知识和 Skills 随任务输入快照交付；审核、取消、幂等、成果、PR 和发布仍由业务服务管理。PR 编号、仓库、分支和提交 SHA 必须匹配；模型输出不能覆盖业务定位字段。
- 每日分析等文本生成改用 Agents 默认模型网关。原有知识库保留，Office 文档解析使用独立 Worker；原项目没有 AI Knowledge 插件，因此无需迁移此插件。
- 保留应用实际使用的 Workflow、Scheduler、通知、出站代理和业务迁移。经典导入命令保留业务数据导入用途。
- 框架配置、CDN 构建和包内导入映射合并到新模板方式；保留应用自己的布局、项目切换器和业务页面。修复英文界面数据源分类匹配导致卡片消失的问题。
- `.npmrc` 的默认 registry 和 `@nocobase` scope 均使用 `https://registry.npmjs.org`；锁文件已重新解析、去重，并同步最新版依赖所提供的 Skills。应用源码和锁文件不含旧源信息。

## 首次配置与交付

1. 在“AI 团队 → 模型”添加模型服务并设置默认模型。
2. 在“Runner”页面连接运行环境；在“Agent”页面创建团队可调用的 Runner Agent。
3. 在“数据接入 → 网站源码”选择 Agent，配置仓库、基础分支和目录范围。研究任务可不设置仓库。
4. 连接所需安装包单独构建和分发，不放入应用镜像：

```bash
pnpm nocobase cli build
pnpm nocobase cli build --runner
```

本轮已构建当前主机的 Linux x64 安装包（包含主机 Node），保存在 gitignored 的 `storage/runners/dist`。其他目标平台需另行构建。部署时将产物目录挂载到应用的同名存储目录。

Runner 必须可信。只读阶段、允许路径和逐步发布的要求会写入执行指令，回执进行业务校验；这些指令本身不是文件系统或 Git 工具的强制沙箱。
