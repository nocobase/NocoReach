# 成员、项目与角色

在「设置 → 成员与角色」中管理成员和角色，页面用「成员」「角色」「待接受邀请」三个标签切换；API 密钥是另一个独立的设置入口。每个项目都有自己的成员：角色决定一个人能做什么，所在项目决定他在哪些项目里做。

## 邀请成员

1. 打开「成员与角色」，在「成员」标签选择「邀请成员」。
2. 在「邮箱」里填写一个或多个邮箱：每行一个，或用逗号、空格分隔，一次最多 50 个。
3. 在「加入的项目」里选择项目，可以不选。被邀请人以「成员」角色加入这些项目，之后可以再调整角色。
4. 发送后，对话框逐个显示结果：
   - **已发送邮件** / **邮件未发送，请复制链接**：新邀请。未配置邮件或投递失败时，复制显示的链接私下发给对方；关闭后如需再次分享，在「待接受邀请」里使用「重新生成链接」。
   - **已加入项目**：对方已经是成员，直接加入了所选项目。
   - **已是成员**：对方已经是成员，且已在这些项目里。
   - **未邀请**：例如该邮箱已有待接受的邀请，或超出了你能授予的权限。

邀请有效七天，只有对方主动接受后才加入。新账号打开链接后设置姓名和密码；已有账号使用被邀请的账号登录后接受，也可以在账号菜单的「我的邀请」中接受。不要使用其他人的账号接受邀请。

重发或重新生成会立即使旧链接失效，并重新计算七天有效期。撤销后的邀请不能接受。新账号邀请的链接只能由原邀请人重新生成；其他管理员可以撤销。同一邮箱同时只能有一份有效邀请。接受时会重新检查邀请人是否仍有授予权；所选项目若已被删除则跳过。

## 调整成员

成员列表显示每个人的角色和所在项目；角色范围为「全部项目」的成员显示「全部项目」。

成员行的操作菜单提供「编辑成员」和「移除」：

- **编辑成员**：勾选角色，并在「项目」中加入或移出项目。你只能调整自己可访问的项目。编辑期间若另一位管理员改了该成员，保存会提示冲突并保留当前选择；重新打开核对后再修改。
- **移除**：立即收回业务访问资格并移出所有项目，保留账号、历史任务和成果。成员的个人密钥随之失效；组织密钥不受创建者离开影响。

新建项目时，创建人自动加入该项目。系统管理员在系统中单独管理，不能在此修改；这里也不能修改自己或移除最后一名业务管理员。

## 管理角色

「成员与角色」的「角色」标签列出内置的「管理员」「成员」和自定义角色。内置角色只读：管理员拥有全部能力并覆盖全部项目；成员可以在自己所在的项目里查看数据、运行研究与分析、创建和处理任务，并使用所有接入站点。

新建或编辑角色时依次选择：

1. **项目范围**：「我参与的项目」只在成员加入的项目里生效；「全部项目」在所有项目里生效，包括以后新建的项目。
2. **项目内的工作**：查看项目数据、运行研究与分析、创建和处理任务、编辑项目设置（项目知识、剧本、分析规则等）。
3. **接入站点**：在「使用」里勾选站点（可全选），持有者可以查看这些站点的数据并手动同步、搜索和测试；「配置站点」一项涵盖所有站点的连接、凭据、断开和清空数据。
4. **应用管理**：新建项目、管理成员和角色、管理组织 API 密钥、管理技能库、管理 AI 团队、管理网络与演示数据。这些对整个应用生效，与项目范围无关。

页面入口会随能力自动显示，不需要单独勾选。多个角色的能力和项目范围分别合并。管理员只能授予自己拥有的能力；没有成员持有的自定义角色才可以删除。

角色修改后，下一个请求就使用新权限。编辑期间角色被另一位管理员修改时，保存会提示冲突并保留草稿。

## 升级说明

升级到此版本时，按旧方式（逐个操作、逐个项目）配置的自定义角色会被删除，持有这些角色的人改为「成员」角色；所有现有成员会加入所有现有项目，因此升级后每个人仍能看到原来的项目。请在升级后按新方式重新创建需要的自定义角色，并按需把成员移出项目。

个人与组织密钥在 [API 密钥页面](API-KEYS.zh-CN.md) 管理；组织密钥的服务账号会加入密钥所选的项目。上线前的密钥换发与备份恢复仍按 [切换说明](ACCESS-CUTOVER.md) 安排。
