# 成员、邀请与角色

在「设置 → 成员与权限」中管理成员和角色。成员资格对整个 NocoReach 应用生效；角色中的项目选择只限制该操作可访问的数据，不创建逐项目成员体系。

## 邀请成员

1. 打开「成员」，选择「邀请成员」，填写邮箱并选择一个或多个角色。
2. 发出邀请后，对方仍未获得业务访问权。邀请有效七天，只有主动接受后才加入。
3. 新账号打开链接后设置姓名和密码；已有账号使用被邀请的账号登录后接受。已有账号也可以在尚未加入的提示中选择「我的邀请」。不要使用其他人的账号接受邀请。
4. 邮件是可选渠道。未配置邮件或投递失败时，可以复制生成的链接，私下发给受邀人。链接不会出现在列表或管理操作记录中；关闭后如需再次分享，使用「重新生成链接」。

「待接受邀请」合并显示新账号和已有账号的邀请。重发或重新生成会立即使旧链接失效，并重新计算七天有效期；操作前会要求确认。撤销后的邀请不能接受。重复接受不会重复授予角色。

新账号邀请的链接只能由原邀请人重新生成；其他管理员可以撤销。已有账号的邀请可由有权授予其角色的管理员重新生成。发出新邀请前，应先在列表中处理同一邮箱的待接受邀请。

接受时会重新检查邀请人是否仍有授予权、账号是否启用、角色是否存在，以及角色是否超出原邀请的权限上限。检查失败不会留下半加入的账号或角色分配。角色扩大、邀请人失权等情况下，请联系管理员重新确认权限并发出新邀请。

## 分配多个角色和移除成员

成员行的操作菜单提供「修改角色」和「移除」。多个角色的允许操作及其各自数据范围合并；任务负责人、审核前置条件、草稿会话隔离和密钥限制继续生效。

移除成员会立即收回业务访问资格，并保留账号、历史任务和成果。成员的个人密钥也随人员资格失效；应用组织密钥不因其创建者离职失效。系统管理员在系统中单独管理，不能在此修改；这里也不能修改自己的角色或移除最后一名有效业务管理员。

## 管理角色

「角色」列出内置业务管理员、成员及自定义角色。内置角色在这里为只读；系统管理员身份不会通过业务角色页面授予。

新建角色时，填写名称和稳定标识，分别选择：

- **页面与团队设置**：控制导航及设置可见性。仅可见页面不会自动获得业务操作权。
- **操作与数据**：展开相应业务，选择操作，并为每个项目操作指定「全部项目」或若干项目。应用级操作会明确标示。

例如，一个角色可读取项目甲的任务，另一个角色可创建项目乙的任务；组合后不会因此获得项目甲的创建权限。管理员只能授予自己有权授予的业务权限。无角色分配的自定义角色才可以删除。

角色修改后，下一个请求会使用当前权限。编辑期间角色被另一管理员修改时，应刷新后重新核对，不能用旧内容覆盖。完整密钥自助页面将在后续阶段提供；上线前的密钥换发与备份恢复仍按[切换说明](ACCESS-CUTOVER.md)安排。
