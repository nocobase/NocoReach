# 演示数据：生成、重置与清除

「设置 › 演示管理」给管理员一键生成一套虚构的演示数据，用来体验 NocoReach 的各项功能；用完可以重置或清除。仅在演示环境（`NOCOBASE_DEMO_MODE=true`）中显示并生效。

所有内容都是虚构的：人物、讨论、指标和历史成果不代表 NocoBase 的真实客户、流量或业务。

## 包含什么

演示讲的是 NocoBase 市场团队用 NocoReach 做增长的故事，中文和英文各一套（同一个团队，人物和内容按语言编写）。

| 数据源     | Google Search Console / GA4（56 天）、网站内容与审计、GitHub、论坛、npm/PyPI/Docker、Hacker News、X、Slack、Discord、关键词研究与排名跟踪、域名与 Lighthouse、Reddit、趋势、竞品、AI 搜索 |

## 外部服务

演示项目不连接任何外部服务：

- 网站、Google、GitHub、社区、关键词等请求都由应用内置的模拟数据在本机回答，走的仍是正式的连接、采集、解析和保存流程，所以页面上的刷新、同步和明细查询都能用。模拟数据没有覆盖的请求会直接拒绝，不会发出去。
- 环境启动时创建并启用「Demo model」默认模型。清除、重置或生成失败都保留它，不再保存和恢复其他默认模型。Demo 环境的业务 AI 和任务执行使用模拟服务。
- 演示项目不参加自动的每日分析，首页和「机会」里保留手写的洞察和机会；点击「更新分析」可以手动跑一次（使用模拟模型），定时重置会恢复手写内容。
- 演示项目的任务自动交给 NocoReach 演示 Agent，支持分析、页面修改草稿和文章草稿，结果明确标注为模拟。它像真实 Runner 一样执行约半分钟：思考、读取任务资料、读取演示站页面和搜索数据、对照项目知识、写稿并提交，过程可以在任务的「技术详情 › 运行历史」里实时查看，执行中也可以停止；审核后以「模拟发布」结束，不创建真实 PR，也不调用真实 Runner。停用适配器后相关操作会失败，不会自动切换到真实调用。
- 不会发送邮件或外部通知。

## 操作

1. 以管理员身份打开「设置 › 演示管理」，选择语言，点击「生成演示数据」。页面显示进度，生成通常在一分钟内完成。
2. 在顶部项目切换器里选择带「演示」标记的项目开始浏览。访客不需要密码：在登录页右下角或打开 `/main/demo-sign-in` 选一个账号直接进入，登录后在右上角头像菜单的「演示账号」里随时切换，体验不同岗位看到的内容。用 `/main/demo-sign-in?as=<用户名>` 可以直接以某个账号进入，适合嵌入官网页面。
3. 「清除」清空当前实例的全部项目及业务数据，包括原有项目、任务、附件、采集数据、知识、机会、新旧 Agent 对话、执行记录及模型用量记录；同时停用本次生成的演示账号，删除演示角色，保留环境的 Demo 模型。「重置」先做同样的清空，再按所选语言生成全新演示数据。管理员和其他原有账号、全局 Agent/Runner/模型/网络配置、全局技能及安装迁移记录会保留。两项操作仅在演示环境中可用，未生成过演示数据时也能使用。执行前会提示完整清理范围，清空无法撤销。

生成失败时同样清空演示实例的全部业务数据，保留管理员和系统配置；如果清理也中断，记录会保留，重新生成前会继续清理。页面显示失败原因，可以重新生成。已有同名账号不会被接管或改密码，遇到冲突会终止生成。服务在生成中途停止时，十分钟后视为中断，下次生成会先清理残留。

## 演示环境的只读保护

演示环境（`NOCOBASE_DEMO_MODE=true`）中，普通请求的写入默认被拒绝，管理员仍可以通过页面生成、重置和清空数据。非演示环境（`false`，默认）下，页面、接口、命令行和定时任务都会拒绝全量清空或重置。存在执行中的任务、对话或 Google 同步时，先停止它们再操作。需要定期清空并恢复演示数据时，可以设置定时重置，清理范围同页面操作：

在「设置 › 演示管理」的每日重置区域选择时间、时区和语言并保存。这是唯一的定时重置配置，以上一次生成的管理员身份执行。

## 命令行

命令行和定时任务使用同一套生成、清除和重置服务，在演示环境的只读保护下也能执行。首次生成必须提供管理员用户 ID：

```bash
pnpm nocobase demo-mode data status
pnpm nocobase demo-mode data import --actor <管理员ID> --language zh-CN --dry-run
pnpm nocobase demo-mode data import --actor <管理员ID> --language zh-CN --force
pnpm nocobase demo-mode data reset --force
pnpm nocobase demo-mode data clear --actor <管理员ID> --force
```

`--dry-run` 只预览操作和参数，不启动应用、不修改数据。`reset` 省略语言时保留当前语言，省略管理员 ID 时使用上次生成者。修改数据必须加 `--force`，输出不包含演示账号密码或模型密钥。

## 配置项

| 环境变量                             | 配置                        | 说明                                                                 |
| ------------------------------------ | --------------------------- | -------------------------------------------------------------------- |
| `NOCOBASE_DEMO_MODE`                 | `demoMode.enabled`          | `true` 为演示环境，`false`（默认）为普通部署                         |
| `NOCOBASE_DEMO_WRITABLE_COLLECTIONS` | `demoMode.allowCollections` | 逗号分隔的逻辑集合名（如 `nrTasks`），部署层面允许访客写入；默认为空 |
| —                                    | `demoMode.quickSignIn`      | 是否提供免密切换演示账号，默认 `true`                                |

模拟模型的地址由应用自动推导，不再需要配置；模拟模型和在线对话的开关在「演示管理 › 模拟与 AI」里设置；在线对话始终使用模拟模型，不能选择真实模型。

## 接口

管理员（`settings:demoMode.data` 权限）可以直接调用：`GET /api/demoMode/data` 查看状态，`POST /api/demoMode/data/import`、`/clear`、`/reset` 生成、清除和重置，请求体可带 `{ "language": "en-US" }`。生成和重置立即返回，进度在状态的 `importing.percent` 里。

## 已知限制

- 小红书、哔哩哔哩、YouTube 需要浏览器采集器，演示项目暂不接入，页面显示为未连接。
- 模拟模型只会回答预先写好的几类问题（任务、搜索数据、机会），其余问题给出标明「演示模型」的通用回答。

## 管理配置

「演示管理」使用演示插件自带的管理页，分为「概览」（演示数据、访客入口和嵌入代码）、「每日重置」「访客写入」「模拟与 AI」四个标签。查看数据和管理数据使用 `demoMode.data` 的 `read/manage` 权限；查看配置和修改配置使用独立的 `demoMode.configuration` 的 `read/configure` 权限。只有对应权限的卡片和操作才会出现，服务器同样检查权限。

每日重置可选择时间、时区和语言，并预览下一次执行时间。保存会替代旧的部署定时配置；关闭后不再定时重置。错过的执行不补跑，夏令时重复时刻最多执行一次、不存在的时刻跳过。手动重置仍可使用。

「访客写入」默认不开放任何业务集合，管理员可以选择整个集合放行（逻辑名，例如 `nrOnlineAgentRecords`、`nrSnapshots`、`nrTasks`）。放行后该集合的新增、修改、删除都允许，但仍受原有业务权限约束，不会授予普通访客管理权限。要让访客和在线 Agent 对话（得到模拟回答），开放 `nrOnlineAgentRecords`；只读观察角色本身没有在线 Agent 权限。项目知识写在 `nrSnapshots` 里，开放它也会让其他快照类数据可写，请按演示需要选择。登录必需集合与部署配置的例外单独显示。

Agent 模拟分别控制模型回答、外部数据源和 NocoReach 演示 Agent。禁用后拒绝相应演示调用，不会启用真实服务。演示 Agent 没有真实 Runner 执行凭据，也不参与真实效果统计。

修改后点击该卡「保存」并确认；其他卡的草稿保留。如果其他管理员已经修改同一份配置，服务器拒绝覆盖，刷新前会询问是否放弃草稿。离开页面时同样提示未保存的修改。

### 启用任务演示

在「演示管理」中开启「NocoReach 演示 Agent」，并在「访客写入」中开放 `nrTasks` 和 `nrSnapshots` 两个集合。

然后在「机会」中交给 Agent，进入任务确认开始，查看模拟产物并人工审核。无需连接真实 Runner 或仓库，原来的默认 Agent 设置会保留。业务权限仍生效；其他集合继续受只读保护。

当前内置演示 Agent 使用预设的双语草稿，并带入任务标题和简报；不会像真实模型一样自由推理。应用开发者可以替换 `server/nocoreach/demo-data/demo-agent.ts` 中的实现，保持输入输出契约即可。

## 独立演示环境

演示实例与正式实例使用独立数据库和存储。清除、重置和生成失败后的清理都清空业务数据，保留管理员、系统配置和 Demo 模型。演示账号清除时停用，下次生成复用。Demo Agent 由环境决定，未带演示标记的新记录也不会触发真实 Runner；未适配的数据源请求会被拒绝。每日重置统一在演示管理页配置。
