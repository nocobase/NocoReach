# ACME 演示数据

演示模式包含同一虚构品牌的两个独立产品。项目名称、人物、讨论、指标和历史成果都用于演示，不代表真实客户或线上发布。

| 项目     | 域名               | 业务场景           | 任务 | 知识资料 | 待处理机会 | 已交办／已忽略 | 观察项 |
| -------- | ------------------ | ------------------ | ---: | -------: | ---------: | -------------: | -----: |
| ACME     | `acme.example`     | 项目管理与团队交付 |   47 |        8 |         12 |          14／2 |      6 |
| ACME CRM | `crm.acme.example` | 销售协作与客户跟进 |   39 |        8 |          8 |          14／2 |      6 |

任务数包含归档、取消和页面发布情景。列表会按当前筛选条件显示其中一部分。两个项目各有约 16 个月的搜索与访问日明细，年度访问报表还可比较上一年度。另外包含社区讨论、仓库动态、关键词、竞品、AI 搜索、媒体内容，以及每个项目 4 组历史助手对话。数据随生成日期移动，中文和英文都可生成。

默认自动登录的管理员在每个项目都有 3 项“等待我处理”的任务，包含待启动与待审核。其他成员按自己的职责查看任务，查看权限不因演示数据而扩大。

两个项目各新增 12 组历史内容工作，覆盖一年多的需求发现、讨论、修改与审核，也能在社区与版本发布记录中找到相应背景。任务的创建、稿件、评论、完成与效果计算按实际先后排列。成果从演示采集器产生的页面日明细计算，包含上升、下降、持平、样本不足和等待观察。

“观察中”每个项目都有 6 条正在观察的信号，显示起始值、当前值、变化比例和各自的截止日期。数值按已采集的页面日明细计算，历史分析保留每日判断；最近结束的观察包含转为机会、恢复正常、不需要行动、到期和人工忽略五种情况。

“已处理”关联每个项目的 12 组历史工作，首次发现和交办时间跨越多个自然月。任务中的 Agent 记录包含读取材料、工具输入与结果、稿件保存、耗时和 token 用量；部分任务有失败重试或退回后的第二版。Activity 记录启动、页面关联、每次交付、退回、重交、批准与发布状态，交付记录关联到具体版本。未启动的任务仍保持未执行状态。这些都是明确标记的模拟执行记录，不是实际模型调用或发布凭据。

搜索支持最近 7 天、28 天、3 个月、6 个月、1 年，以及保留范围内的自定义日期。Search Console 保留 16 个月，因此“一年与上一年”的搜索对比无法覆盖完整上一年度，会如实标记缺失；一年内的当前趋势完整。访问数据包含工作日与周末差异、不同产品的月度季节变化。

## ACME：从 Excel 到第一次清楚的交付

可以从“机会”开始查看以下场景：

- 社区近两周有 5 个 Excel 导入提问，其中 3 个待回复。教程需要解释负责人匹配、日期格式、预览和失败行重试。
- “项目管理软件”的排名改善，但点击率偏低，需要核对首页标题和摘要是否回答团队的需求。
- 定价页访问增长，团队仍不清楚成员和客户访客的区别，适合补一份十二人团队案例。
- “ACME vs Nimbus”出现对比需求，现有页面较薄，需要统一评估范围。Nimbus 也是虚构对比样例。

任务进一步覆盖看板在制品、依赖排期、访客权限、项目周报、客户验收、工时、跨时区日历、结项归档和项目交接。成果包含改善、下降、持平、样本不足和等待观察；通知说明被退回、缺乏证据的估时宣传被取消、过期截图被归档。

## ACME CRM：从客户导入到续约

第二个项目有自己的来源、机会、任务和讨论。可以沿着客户导入与去重、线索分配、销售阶段、报价版本、客户转交和续约准备逐步查看。

例如，导入演练涉及 1,280 行公司资料、86 条重复项和 14 条未分配记录，逐组确认后保留 1,194 家公司，另行核对 320 位联系人；报价稿因版本说明不清被退回；价格页效果下降，需要继续核对访客需求；续约指南只有少量样本，暂不能判断效果。这些数字均为虚构情景。

切换项目时，搜索、知识资料、社区、助手机会回答和任务关联都会使用所选项目的数据。不同演示账号只看到其有权访问的项目。

## 可以重点查看的任务

- ACME 的排期依赖：固定 D13 发布里程碑，解释上游晚两天后的冲突、减范围与改日期两个选择。
- ACME 的周报：从完成任务数量改为风险与决定，保留初稿、具体审核意见和第二版。
- ACME CRM 的客户导入：公司和联系人分别对账，保留合并撤销、失败恢复和历史跟进。
- ACME CRM 的销售阶段：逐项解释进入条件、客户证据、异常商机和加权金额的含义。
- ACME CRM 的报价：48,000 与 43,200 两个版本，折扣批准、发送结果、客户接受分别记录；仍缺资料的稿件保持待修改。

两个项目的全部任务都有目标、验收条件与边界。已交付任务提供具体工作文档，包含表格、案例或操作分支；八条任务保留两个版本。所有案例均重新编写，真实业务任务仅用于参考结构，未导入真实业务材料。

## 如何看到新版数据

新版内容通过现有演示数据生成器生效。部署包含本次修改的版本后，新建演示数据或下一次自动重置会生成 ACME 与 ACME CRM。已有数据不会仅因修改源文件而立即改名。

管理员也可以通过 Demo Mode 的 CLI 或 API 重置数据；“设置 → 演示管理”用于查看状态与定时重置计划。重置会清理演示环境的业务数据及访客新增内容，再重新生成；需要保留的内容应先保存。普通安装不会自动导入这套数据。

旧版演示账号会保留原有账号 ID 和密码，邮箱改为 `acme.example`。此处理只适用于插件登记为本演示数据集所有的账号，不会修改同名的其他用户。
